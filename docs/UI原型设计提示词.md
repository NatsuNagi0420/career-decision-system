# 青穗集 UI 原型设计提示词

更新日期：2026-10-14。
用途：复制主提示词到原型工具。配合现有页面截图和穗奈透明头像使用；原型中的数据和交互均为演示，不代表已连接模型或后端。

## 主提示词

你是一位资深产品设计师兼前端原型设计师。请为「青穗集」重新设计一个可交互的中文求职助手原型。

这不是招聘网站、营销官网或泛用聊天机器人，而是帮助求职者「整理经历 → 对照岗位 → 明确能力缺口和下一步行动 → 形成简历草稿」的 Agent 工作台。

设计目标：新用户进入 5 秒内知道从哪里开始，完成一个演示流程后能看到具体产出，而不是只得到一长段聊天文字。保留品牌角色「穗奈」，但不要让人物装饰抢走任务和结果的注意力。

### 1. 产品定位和主线
- 主要用户：应届生和求职方向不清楚的初级求职者。
- 核心价值：把模糊的求职困惑变成有依据、能执行的下一步。
- 保留四个任务入口：「先补我的经历」「对照岗位」「缺口和练习」「写一份简历」。
- 新用户突出「先补我的经历」，其余入口为次级选择；用户有资料后再突出「对照岗位」。不要把四个入口始终做成同等权重的大广告卡。
- 不扩展课程商城、社区、招聘投递、订阅付费、公司管理等无关模块。

### 2. 视觉方向
- 关键词：温暖、安静、清晰、可信、成熟；不是幼稚可爱，也不是冷冰冰的企业后台。
- 暖白或轻纸色背景、深色正文、克制青绿强调色，少量麦穗元素。
- 参考成熟对话产品和文档工作台的信息组织，但不要照搬品牌或现成页面。
- 不使用紫粉 AI 渐变、霓虹、液态玻璃、整页薄荷绿、到处发光的边框或巨大圆角。
- 中文字体优先；正文 14–16px；清楚的标题、正文、辅助文字层级；统一间距、边框、圆角和图标。
- 留白要服务于阅读和分区，不要出现大块无用途空白；也不要为了填满页面堆假图表和装饰卡片。
- 穗奈使用现有透明人物素材，适合放在欢迎区、对话头像和少量状态反馈中，不重新生成角色。如果没有素材，先用简单头像占位，不换成新的动漫人物。

### 3. 工作台结构
- 桌面以左侧轻量导航、中心对话/任务区、可展开的成果区组织。成果区只在有内容或用户主动查看时出现。
- 左侧提供新对话、最近对话、已有成果的访问入口和账号设置；不要堆内部技术导航。
- 中间让用户与穗奈沟通、补充经历和确认资料；输入框明确、稳定，不遮挡内容。
- 成果区展示当前画像、岗位对照、缺口与行动建议、简历草稿，默认打开与当前任务有关的内容，而不是同时塞满全部卡片。
- 当前任务、等待用户确认、已经完成、出错可重试等状态要可理解。不要展示 token、模型推理链、数据库 ID 或研究者调试面板。
- 正常桌面状态至少留出约 560px 的可读内容宽度。中等屏幕把成果区改成抽屉，手机用「对话 / 成果」切换；不要硬挤成三栏。

### 4. 必须设计的页面和状态
A. 登录/注册：品牌简洁，表单有清楚标签；云端模型授权可理解、可选择；不要用巨幅人物或营销文案淹没表单。
B. 新用户首屏：简短招呼、一个明确主按钮、四个任务入口、可输入的示例，不展示假进度和空统计图。
C. 补充经历：通过对话整理教育、技能、项目和偏好；整理后出现确认卡，展示将保存的具体内容，用户可确认或返回补充。
D. 岗位对照：展示 2–3 个演示岗位；每个岗位有要求原话、能够对应的经历、未能对应的地方，并提供「看缺口和练习」的下一步。
E. 缺口和行动：区分「尚未提供对应经历」与「需要学习的知识」；以少量优先事项呈现短期行动建议。题库有已收录练习和提示，也要有暂无收录的空状态。
F. 简历草稿：A4 感的干净预览、模板切换、字号/间距调整、空内容提醒、改进建议、「打印 / 另存为 PDF」「复制 Markdown」。不要把应用背景和角色装饰带进打印简历。
G. 至少展示资料不足、等待确认、处理中、无对应练习、错误重试这些关键状态。

### 5. 真实能力边界
- 岗位来自目录样本，不一定仍在招聘。显著但不刺眼地写「目录参考样本，招聘状态未核实」；不要包装成实时招聘平台。
- 不显示没有依据的「匹配度 96%」、录用概率或能力评分；用对应的要求和经历解释推荐。
- 缺少某项经历不等于用户不会；请写「还没有对应经历」而不是直接判定「你不具备」。
- 练习来自已收录题库；没有对应题目时明确提示暂无收录，不现场编题充当题库。
- 简历只使用用户已确认的经历，缺内容要提醒，不编造工作经历、成绩或项目数据。
- 简历改进建议先指出缺项和表达依据，不假装当前产品已具备简历文件上传、解析、全文自动润色或 Word 一键导出。
- 文件上传等未来能力可列在设计说明里，但不要放成当前可用按钮。
- 原型以本地模拟数据和前端交互实现，明确标注「演示数据」；不调用真实模型、后端或收费接口。

### 6. 演示流程和交互
使用一位虚构的计算机应届生作为演示用户：学过 Python 和 SQL，做过一个校园数据统计项目，想了解数据分析相关岗位。所有经历、岗位和题目都注明演示用途。

演示链路：点击「先补我的经历」→ 输入经历 → 穗奈整理出待确认卡 → 用户确认 → 查看画像 → 对照演示岗位 → 查看缺口及已有练习 → 查看简历草稿 → 切换模板、打印或复制。

按钮必须有合理的前端反馈或状态变化；确认资料前后状态要不同；不支持的动作不要用假成功提示冒充完成。打印可以调用浏览器打印，不伪装成已生成下载文件。

### 7. 输出和验收
- 请产出可交互高保真原型，不只给文字方案或静态首页。
- 桌面按 1440px 设计，并检查 1280px 中等屏幕与 390px 手机适配。
- 如果生成代码，优先 React + TypeScript，组件和样式可复用，不堆重复页面；每个新增源文件开头写统一职责注释。
- 提供颜色、字体、间距、圆角、按钮、卡片、输入框和状态样式的设计规范。
- 使用自然、具体的中文，不写「赋能」「开启未来」「解锁无限可能」等空泛口号。
- 先确保流程可理解，再做精致细节；不要把 Agent 做成只会聊天的聊天窗，也不要做成难懂的驾驶舱。
- 最终说明哪些是可交互原型、哪些是模拟数据、哪些是未来设想。视觉好看不能被当作功能已实现。

## 第二轮打磨提示词

请保留青穗集的产品主线、穗奈和已有交互，不继续增加功能，也不要整体换皮。检查并改进以下问题：
1. 新用户的第一步是否足够明确；每个结果是否有一个清楚的下一步。
2. 是否仍像营销首页、通用聊天机器人或卡片堆叠后台；如果是，收敛为真正的求职任务工作台。
3. 是否存在无用途的大块留白、三栏过窄、字号层级混乱、同一屏多个主按钮。
4. 画像、岗位、缺口、简历是否各有适合内容的排版，而非全部套用同一种卡片。
5. 手机输入框是否遮挡内容，成果切换是否方便，表单是否易读易操作。
6. 等待确认、资料不足、暂无题目和请求失败是否给出了可理解的反馈。
7. 岗位与经历的对应依据是否容易找到；是否存在虚假百分比或把演示能力当成真实功能的问题。

请给出修改后的原型，以及最重要的五项具体修改。不要只解释设计理念。
