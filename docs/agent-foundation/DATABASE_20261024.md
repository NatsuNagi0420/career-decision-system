## 读取与导入

HTTP、模型工具和用户确认保存都使用 CareerWorkspace.catalogue。没有运行时 JSON 副本、全局快照缓存或缺库时的演示数据回退。单条 SQL 读取一致视图，并校验内容指纹。

表包括 catalogue_state、catalogue_jobs、catalogue_directions、catalogue_batches、catalogue_imports、catalogue_materials 和 catalogue_review_queue。保留来源证据不等于维护另一套数据库；个人工作台 8 份岗位上限也不等于公共库容量。

根目录导入新批次：

~~~powershell
npm run catalogue:import -- --archive "新批次.zip" --review "该批次清洗规则.json"
~~~

其他部署通过 --database 指向同环境的唯一 agent.sqlite。命令先编译 Agent，变更前在线备份，再从主库读取基线、清洗去重、检查版本冲突，在同一事务写入岗位与证据并读回对账。临时交换文件完成即清理；相同 ZIP 和规则不重复新增。修改已导入批次规则会拒绝，不能无声覆盖原始证据。

正常导入岗位无需重启服务。本次已重启 8110 后端和 5173 前端，新版数据库读取逻辑已启用。
