# 执行记录与命令输出

## 用户操作

- 对话中的“执行进度”直接显示真实命令、文件路径、搜索内容与结果摘要；默认展示最近 3 项，可展开前面的操作。
- 点击任意操作，或聊天顶部的“执行记录”，在右侧查看详细记录。
- 右侧分为“操作与输出”和“任务计划”；可切换历史轮次，复制命令或输出，展开调用参数。
- 命令展示实际传入的 command、stdout、stderr、退出码、耗时；结构化文件工具展示真实路径，不虚构等价 shell 命令。
- 文件版本可直接切换到原来的文件预览；两种详情复用一个侧栏。
- 窄屏使用抽屉，支持 Esc、关闭按钮和点击抽屉外空白区域收起。4K 使用宽侧栏。

## 数据与边界

- execution.ts 合并同一 run_id + call_id 的工具消息与实时事件。实时开始事件立即出现，最近事件被裁剪后仍能从持久消息恢复历史参数与返回内容。
- 非零退出码即失败，不因为工具返回过结果而展示成功。
- 区分待执行、执行中、等待确认、失败、停止和待核实；缺少历史开始事件时，不保证该调用从未执行，也不自动重跑。
- 任务计划来自实际 plan_tasks 成功结果或 plan.updated，不虚构计划进度；内部模型思维不在此展示。
- 后端现有敏感值脱敏与结果长度限制保持不变。日志可能包含命令涉及的用户文件内容，不应分享未审查的日志截图。
- 当前命令输出在完成时返回，不是逐行实时终端；长输出沿用服务端截断标记。复制得到的是已保存、已脱敏的记录，而非保证完整的原始进程日志。
- 输出按纯文字渲染，不执行其中的 HTML 或脚本。折叠的操作详情延迟渲染，避免大量文件参数同时展开占用 DOM。
