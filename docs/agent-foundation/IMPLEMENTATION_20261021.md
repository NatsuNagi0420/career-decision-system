# TypeScript Agent 底座：本轮实施结果

## 1. 交付范围

本轮把约定的「自有通用任务底座」落成可独立启动的一版，不把它说成整个求职产品已经完成，也不把脚本测试说成真实模型验收。保留 React、像素字体、开机动画和穗奈素材；当前运行服务以 TypeScript Agent 为准。

默认链路：React → 本机 TypeScript HTTP/SSE 服务（8110）→ 自有决定/执行/观察循环 → 明确开放的工具 → 独立资料副本与成果版本。模型由用户接口或可选官方中转提供，执行代码的权限不等于模型权限。

## 4. 实测后修复的问题

1. 不带正文的 POST 原先错误发送 application/json，Fastify 拒绝空 JSON；修复并补客户端测试。受影响的测试连接、停止、导出、注销均使用同一请求封装。
2. 取消时工具可能正在结束：避免重复工具回复、状态复活以及执行后续工具；已经产生的真实文件不伪装成已撤销。
3. 等待用户确认不再消耗任务执行时长；即时确认也不会被尚未收尾的旧执行段吞掉。
4. 初始消息和任务事件在事务提交后才通知订阅方，减少界面看见回滚事件的风险。
5. SSE socket 不再在首个心跳边界因空闲超时断开，心跳同时重验登录会话。
6. 刷新后恢复事件和正文，异步请求不会覆盖另一段会话；保留当前会话选择。
7. 隐藏文件输入的样式、手机聊天高度和发送按钮可见性、4K 字号，以及审批工具的真正完成记录。
8. 输出用量缺失仍有预算；统一相对路径分隔符和 Windows 大小写的版本链；拒绝保留文件名、元数据地址与链接绕行。
9. 新旧前端明确通过开发入口选择，不再允许仅用 ?legacy=1 把新 API 强行当成旧 API。

## 5. 尚未完成的外部前提与边界

- **真实模型：** 没有读取或使用用户现有真实 Key，没有用真实 LLM 产生结果。请在新版模型设置中配置并测试，再用脱敏资料检验质量、工具可靠性和费用。
- **真实命令：** 当前环境检测不到 Docker/Podman；WSL 可执行文件存在但报告未安装子系统。未安装、启用、重启或创建虚拟化环境。命令不会降级到本机 shell。
- **上传自动化：** Chrome 扩展未开启本地文件 URL 权限，自动代选文件被阻止。产品的普通手工文件选择不依赖扩展权限；后端导入、前端选择器触发和后续流程分别已验证。
- **下载落盘：** Chrome 插件未返回预期 download 事件，无法确认最后保存路径或原生保存对话框是否完成；不得把 HTTP 返回成功说成本地文件保存成功。页面文案已改为「交给浏览器下载，请确认保存」。
- **官方运营：** 中转代码不是已开通的官方模型服务。上游 Key 只在运营服务器配置，客户端仅持有每安装实例的受限凭证；没有完整自动签发、购买、计费或云端管理后台。
- **安全范围：** 这是本机应用，不是经审计的公网多租户执行产品。容器依赖系统内核与可信镜像；绑定输出目录没有磁盘硬配额，仍有资源消耗风险。
- **输入范围：** 目前只能导入文本类资料；PDF/Word 自动解析、正式简历模板排版导出、联网搜索、真实桌面/浏览器代理和自动投递均未实现。
- **职业特化：** 旧版能力没有删除，但没有全部迁到新内核。下一步应迁移一条完整「导入经历→核对事实→简历优化→模板导出」闭环，再扩岗位证据、学习与练习，不能先靠新增很多入口假装特化完成。
