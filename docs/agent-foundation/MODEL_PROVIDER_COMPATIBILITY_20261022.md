# 模型发现与第三方接口兼容 · 2026-10-22

## 使用方法

1. 打开模型设置，选择已有连接或添加连接。
2. 填写接口地址和 API Key，并阅读、勾选模型服务授权。
3. 点击「拉取模型列表」，搜索并从下拉框选择模型。
4. 点击「保存并测试连接」。默认自动检测协议，无需先在高级选项里选择。
5. 查看聊天、工具往返、流式三项结果及分项详情。

无需先保存连接或手填模型名称。只有接口不提供模型列表时，才使用页面中的手动填写选项。返回的列表可能包含不能聊天或不能使用工具的模型，因此仍需测试；不会把列表存在当作连接成功。

本机模型接口需要在高级选项中明确授权。更换接口地址时必须重新填写该服务的密钥，禁止沿用旧地址保存的密钥。未选择 Windows 加密保存的 Key 只留在服务内存，重启或退出后需要重填。

## 兼容改进与限制

- 统一规范化接口地址：接受 API 根地址、/v1 以及完整的 /chat/completions、/responses、/models 后缀，保留自定义前缀。
- 拉取模型使用 GET /models，兼容标准 data 列表及常见 models/data.models 封装；去重、排序并限制异常数据。
- 新连接默认自动检测 Chat Completions / Responses。仅在明确的协议或路径不匹配时尝试另一协议；401、403、429、503 等不通过换协议盲目重试。
- 对明确拒绝的参数做有限协商，覆盖 max_tokens/max_completion_tokens、stream_options、stream、tool_choice、strict、Responses include 等。
- 网关在流式请求下返回有效普通 JSON 时可继续聊天，但明确标记为非流式。聊天通过、工具失败时保留聊天能力。
- 连接测试预算提高到配置允许范围内最大 2048 输出 token，减少推理模型被过低上限误判的情况。测试可能计费。
- 错误信息按鉴权、权限、额度、无可用通道和 HTTP 状态分类，不回显供应商原始错误体。
- 这不是对任意第三方协议的全兼容承诺；仅提供 Claude/Gemini 原生接口、禁用 /models 或自定义鉴权的网关仍可能需要适配。
