# 当前 Agent 运行时架构

本文记录 `5173 → 8110` 默认开发链路的实际实现。前端是穗奈的职业规划产品界面，`8110` 是 TypeScript Agent 服务；两者通过 `/api/v1/agent/*` 通信。项目默认使用本机 SQLite，模型通过 OpenAI-compatible 接口连接。

当前发布判断：这是可进行 Windows 本机真实内测的 Alpha，尚未完成公网生产验收。8120 已加入账号隔离、令牌轮换/撤销、用量事件、脱敏日志、备份、账号级租约、上游健康告警、PostgreSQL 迁移和异步图片回收；HTTPS、密码找回/邮箱验证、外部监控接收、支付回调和云端编排仍属于部署阶段工作。

## 检查点与续接

每个运行都会把最近安全现场写入 `agent_checkpoints`：已完成的工具调用、尚未确认的工具调用、上下文压缩指纹和检查点状态分别保存。每个工具调用还会先写入 `tool_executions` 收据，执行完成后保存脱敏结果；如果进程在“工具已经完成但消息还没写入”这一窄窗口退出，重启时会回放收据，不重复产生副作用；如果收据仍是 `started`，则标成 `uncertain` 并等待用户确认。事件日志是审计真源，检查点是恢复索引；两者都保留，不用摘要覆盖原始消息。

`AGENT_MAX_STEPS` 只表示检查点间隔，达到后会整理进展并继续执行。`AGENT_MAX_TOTAL_STEPS` 是单个运行的安全上限；达到后运行暂停，界面提供“继续回复”，由新运行继承原上下文并记录 `parent_run_id`、`continuation_count` 与累计 `total_steps`。续接次数受 `AGENT_MAX_CONTINUATIONS` 限制，避免通过连续点击绕过安全边界。

服务重启时，如果最后一个检查点已经是完成状态，运行会确定性收敛为完成，避免重复回复；如果工具结果处于不确定状态，则写入明确的失败结果并标记为 `runtime_interrupted`，不会自动重跑，用户确认后才可继续。

## 运行边界

模型只负责提出回复、工具调用和待确认草稿。模型不能直接写职业业务库，也不能把推测写成用户事实。画像、岗位样本、技能和行动先形成待确认提议，由用户确认后才进入职业工作台；简历事实必须能追溯到用户原话、导入材料或已经确认的职业工作台来源。

能力注册表不是权限绕过层。能力中声明的 `riskTier` 和 `requiresApproval` 用来描述产品能力的风险，实际执行仍由领域工具白名单、`AgentPolicy`、审批服务和 SQLite 版本校验共同限制。R2/R3 能力必须声明需要审批；目前简历交付能力属于 R2，导出仍需用户确认。

待办承诺只表达“下一步可以做什么”。它不会自动发送消息、切换任务、执行命令或确认职业画像。用户点击“接着做”后，前端先认领承诺并把内容填入输入框；真正发送时运行绑定 `obligation_id`，只有运行完成才标记为 `fulfilled`。失败或停止会保留 `claimed` 状态，用户可以重试或放弃。

完全访问权限仍受本地宿主能力、当前沙箱实现和工具白名单限制。它不是管理员权限，也不代表模型可以任意读取账号之外的文件。默认文件工具只访问当前对话工作区；导出成果仍需要审批。

## 能力注册表

当前职业领域声明以下真实能力：

- `conversation_support`：陪用户理清问题、识别缺口。
- `profile_diagnose`：从真实对话整理职业画像和技能待确认草稿。
- `direction_explore`：检索离线职业方向与岗位样本。
- `compare_decide`：对照岗位要求与已有证据形成比较草稿。
- `action_plan`：把差距拆成学习、练习和项目行动。
- `resume_build`：按已确认的事实和目标生成简历预览。
- `artifact_delivery`：在确认后生成可下载的简历文件。

能力元数据可以通过登录后的 `GET /api/v1/agent/info` 查看，其中 `agent_capabilities` 是当前领域能力，`capabilities` 是底层工具能力；也可以调用 `GET /api/v1/agent/capabilities` 只读取领域能力。

## 事件和数据

事件保存在 SQLite 的 `events` 表中，原始消息和工具结果不被压缩覆盖。上下文压缩只生成摘要供模型使用，保留 `source_signature`、省略消息 ID 和前后预算，便于诊断。跨运行待办保存在 `obligations` 表中，删除会话时级联删除；跨账号查询通过 `user_id` 条件隔离。

当前会话快照会返回：

- `guidance`：模型整理的小结和程序进度，不等于职业档案。
- `plan`：模型提出的任务计划，`done` 只是计划状态，不是事实完成证明。
- `obligations`：跨运行下一步承诺及其状态。
- `events`：可回放的执行事件。
- `artifacts`：可预览、下载和本地打开的成果版本。

命令执行会先通过 `tool.output` 事件回传受限的 stdout/stderr 分片，再通过 `tool.finished` 保存完整结果。实时展示最多保留每次命令 16 KB，避免长日志占满事件表；最终结果仍以工具完成事件为准。

项目修改通过 `apply_project_patch` 完成：模型先读取文件获得完整内容哈希，应用层校验 `expected_sha256` 后才写入；一次修改只支持创建或更新 UTF-8 文本，不支持删除。结果会返回 `edit_id` 和精简 diff；`undo_project_edit` 只在当前文件仍保持修改后的哈希时恢复备份，外部改动会触发冲突并停止撤销。

## 主要接口

- `GET /api/v1/agent/info`：运行时、沙箱、工具和能力信息。
- `GET /api/v1/agent/capabilities`：当前领域能力注册表。
- `GET /api/v1/agent/continuations`：从持久任务计划恢复未完成步骤。
- `GET /api/v1/agent/obligations`：读取本人承诺，可按 `conversation_id` 筛选。
- `POST /api/v1/agent/obligations/:id/claim`：原子认领一条下一步。
- `POST /api/v1/agent/obligations/:id/abandon`：明确放弃一条下一步。
- `POST /api/v1/agent/conversations/:id/runs`：发送消息，可带 `obligation_id` 绑定承诺。

## 仍然保留的产品边界

本项目现在具备通用 Agent 底座和职业规划领域实现，但不是云端多租户运行平台；默认数据和事件都在本机 SQLite。岗位库是离线参考库，不能被表述为实时招聘市场。当前模型没有独立、可验证的长期记忆，跨会话小结只作为待核对背景。工作区 `AGENTS.md` 仅解决项目协作规则注入，不等于技能系统、补丁审阅或完整编码 Agent 工作台。职业画像和简历仍以用户确认作为写入边界，避免把模型猜测变成用户资料。
