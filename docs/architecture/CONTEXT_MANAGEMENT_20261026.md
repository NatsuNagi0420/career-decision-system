# Agent 基座上下文管理

日期：2026-10-26

## 目标

模型每次请求都经过统一上下文管理层。业务工作流不再决定是否裁剪历史，也不需要针对职业、简历或文件任务分别写一套特殊逻辑。

## 保留优先级

1. 当前运行的用户消息、助手工具调用和工具结果。
2. 最近的普通对话。
3. 最近一组完整的助手工具调用与对应工具结果。
4. 已有会话小结和被省略的用户原话摘要。
5. 更早的助手回复和工具结果按预算省略，需要时重新调用工具读取。

旧工具调用不会被拆成孤立的 `tool` 消息。助手工具调用与工具结果必须成对保留，避免发送给供应商时破坏消息协议。

## 默认预算

```text
AGENT_CONTEXT_MAX_TOKENS=32000
AGENT_CONTEXT_RESERVE_TOKENS=8000
AGENT_CONTEXT_RECENT_TOKENS=10000
AGENT_CONTEXT_MAX_TOOL_CHARS=12000
```

`AGENT_CONTEXT_MAX_TOKENS` 是未知供应商下的总上下文保守上限；`AGENT_CONTEXT_RESERVE_TOKENS` 是最低安全预留。Runtime 每次发送前还会根据当次系统规则、工具定义、输出上限和压缩摘要动态增加预留，历史消息只能使用剩余空间。普通使用不需要修改这些值。

## 请求级预算

上下文管理器先计算固定部分：穗奈身份与产品规则、当前任务规则、工具 schema、模型输出空间和协议安全余量；随后才计算历史消息预算。这样工具数量变多、切换简历任务或打开完全访问时，不会继续套用同一份历史上限。`model.started` 会记录总窗口、动态预留、历史预算和估算请求大小。

## 结果压缩

工具结果超过单条上限时保留首尾并插入压缩标记。旧工具结果被省略时，模型收到“需要核对时重新调用对应工具”的提示，不把截断内容当作完整事实。

运行事件 `model.started` 会记录估算输入 token、原始输入 token、省略消息数和是否发生压缩，用于定位供应商慢、上下文膨胀和模型上下文限制问题。

## 运行失败与续接

整轮超时不等于任务完成。若当前运行没有未完成工具、没有重复写入风险且预算允许，界面提供一次安全续接；续接会重新计算本轮执行时间，并复用已成功保存的工具结果。

## 业务层边界

职业工作台、简历流程和通用文件工具只负责保存结构化事实、权限和结果。它们可以提供领域资料，但不能自行拼接完整聊天历史。上下文预算和压缩策略由 `agent/src/context.ts` 与 `Runtime` 统一负责。
