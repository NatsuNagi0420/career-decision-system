# 岗位驱动学习

本轮在既有职业工作台中新增“学习路线”，主对话仍用于澄清目标、讲解、提问和反馈。用户不需要重新填写一套画像，也不需要跳转到独立课程产品。

## 使用流程

1. 把岗位原文加入职业工作台，在岗位卡片选择“为这个岗位规划学习”，或直接和穗奈讨论。
2. Agent 读取职业档案与已有学习进度，结合基础和可用时间生成路线草稿。每节包含岗位要求原句、学习目标、先修章节、预计时间、视频搜索词、练习和交付物。
3. 用户在学习路线窗口确认后开始。画像或目标岗位变化时，旧草稿不能直接采用，需要重新规划。
4. 在章节内搜索 B 站教学视频，预览或跳到 B 站，并把合适的资源加入本节。服务器只保存视频元数据与链接，不下载、代理或存储视频。
5. 用户保存笔记和练习成果，明确标记完成或跳过。完成需要成果文字；跳过需要原因；后续章节遵守先修顺序。
6. 再次进入时续接未完成章节。用户可把成果交给穗奈反馈；完成章节的成果以 `learning.{path_id}.{node_key}` 作为职业证据来源，可进一步用于经历核对与简历整理。

学习状态与技能评估分离。打开视频不等于学完，完成章节不等于掌握技能，用户提交的成果也不等于独立认证。画像和简历仍需按现有事实与证据规则处理。

## 实现

沿用当前 Agent 的同一 SQLite 数据库，新增三张按账号隔离的表：

| 表 | 用途 |
| --- | --- |
| `learning_workspaces` | 路线、待确认草稿、章节状态、笔记、成果与版本号 |
| `learning_resources` | 当前账号真实搜索到的视频元数据，供资源关联校验 |
| `learning_searches` | 当前账号最近搜索的十分钟缓存 |

用户修改使用独立 `revision` 防止覆盖旧版本。模型提出路线时同时提交职业 `context_version` 与学习版本；确认前进一步核对画像、技能、目标岗位指纹。已有岗位路线只能带 `path_id` 调整，避免重复创建。未变化的章节保留进度；练习或先修内容变化时重置相关章节状态，保留历史笔记和成果供对照。

模型工具：`read_learning_context`、`search_learning_videos`、`propose_learning_path`。模型不能直接确认路线、标记学完或填写用户练习结果。

HTTP 接口均要求当前账号登录：

- `GET /api/v1/agent/career/learning`
- `POST /api/v1/agent/career/learning/changes`
- `GET /api/v1/agent/career/learning/videos?query=...`
- `GET /api/v1/agent/career/learning/videos/:bvid/subtitles`

搜索请求固定的 B 站 `/x/web-interface/search/all/v2` 接口，并仅解析视频分组，超时十秒、最多返回六项。旧的 `/x/web-interface/search/type` 在当前服务请求中返回 HTTP 412，已改用新接口。结果以 B 站风格的视频条目呈现，显示封面、标题、作者、播放量和时长；用户可以预览、跳转 B 站或加入当前学习章节。封面仅接受 HTTPS `*.hdslb.com`，视频地址由合法 BV 号生成，忽略第三方返回的跳转地址，并清理标题 HTML。资源只能从该账号真实搜索结果中添加。搜索风控或失败时保留站内搜索入口，不编造课程。外部标题属于资料，不能作为模型指令。

字幕在用户主动点击后读取，不自动下载或持久化。字幕接口通过 B 站 WBI 签名播放器接口查询轨道，只接受当前账号先前搜索到的 BV 号，限制返回体大小和字幕行数，并过滤字幕 CDN 域名，不使用旧版 `/x/player/v2` 的字幕列表以避免风控时的错误匹配。B 站登录受限的视频返回 `login_required`，明确提示且不读取本机浏览器 Cookie；没有字幕时返回独立状态。

## 第一版边界

- 学习进度按章节、笔记和练习记录保存；不读取跨域 B 站播放器的播放秒数或自动判断是否看完。
- 不下载视频或保存字幕正文；公开可读的字幕按需显示，登录受限的字幕不绕过 B 站权限。搜索结果不代表已审核的课程质量。播放器受 B 站规则影响，始终提供外部打开入口。
- 复用现有主对话完成讲解与反馈，不复制另一套聊天界面，也不自动把观看历史写成简历经历。
- 数据持久化于当前运行实例的账号数据库。本轮未增加 PC 与云端学习数据的跨实例合并协议，也未执行云端部署。
