# 仓库结构与重构基线

## 当前默认运行链路

```text
web/                         React 19 + Vite，穗奈桌面与用户交互
  └─ /api、/healthz          开发时代理到 8110
agent/                       TypeScript Agent，本机 API 与唯一 SQLite 主库
  ├─ src/                    配置、模型适配、执行循环、工具、审批、文件成果
  ├─ test/                   Agent 单元与接口契约测试
  ├─ var/                    本机账号、会话、岗位库和成果运行数据（不入 Git）
  └─ relay-var/              官方中转凭证与每日配额（不入 Git）
assets/web/                  页面运行时会读取的公共素材
legacy/server-python/        旧 Python/FastAPI/LangGraph/MySQL 实现，只供追溯
scripts/                     导入、备份、验证和本地开发脚本
docs/                        产品、架构、研究笔记和品牌交接文档
spikes/                      一次性技术验证，不作为运行时依赖
```

用户平时只打开 `http://127.0.0.1:5173/`。开发服务是 5173 前端、8110 Agent；官方中转 8120 只有配置官方模型时才需要运行。8110、8120 是服务边界，不是两套用户系统。

## 发布边界

可以进入 Git 的内容：

- `agent/src`、`agent/test`、`web/src`、`web/e2e` 和可复现的构建脚本；
- `assets/web` 中实际被页面引用的素材；
- 不含个人数据、密钥和大文件的架构文档、研究笔记和迁移说明；
- `.env.example`、锁文件和验证命令。

只保留在本机或单独制品存储的内容：

- `agent/var`、`agent/relay-var`、`logs`、`backups`、`tmp`；
- `.env`、SQLite 数据库、运行日志、个人会话和官方中转凭证；
- `docs/参考资料` 中的原始 PDF/网页抓取物；
- `docs/品牌形象` 中的 PSD/KRA/CLIP/ZIP 原画交接包；
- `docs/岗位库扩充` 中的原始岗位交付压缩包。

这些规则只控制 Git，不会删除本地文件。大素材如果未来需要公开发布，应单独使用 Git LFS 或制品存储，不要把原画源文件直接塞进应用仓库。

## 大改前的基线

1. 先在当前目录完成 `npm run check`、`npm test` 和 `npm run build`。
2. 将当前可运行版本作为一个明确的 Git 提交或标签。
3. 后续大改使用独立分支；每次只改变一个边界，例如 Agent 执行内核、岗位匹配、简历工作流或 UI。
4. 不把旧 Python 服务重新接回默认启动，也不在同一项重构中同时切换数据库和前端路由。

这样做的目的不是冻结产品，而是让每次大改都能回答三个问题：当前可运行版本是什么、哪一层发生了变化、失败时如何回退。
