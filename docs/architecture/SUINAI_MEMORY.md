# 穗奈识海

识海是职业助手的长期记忆检索层。主对话仍是入口，识海通过桌面窗口展示记忆和召回依据。前端按用户视频参考的方向，采用 Three.js / WebGL 绘制真正可旋转、缩放的三维星云空间。星云粒子是氛围；可点选的记忆星体和召回光路来自实际数据，不是模型隐藏思维或真实神经活动。

## 数据从哪里来

- 对话回复后的现有只读整理请求，同时返回 `memories`，不为记忆再增加一次独立模型调用。
- 每条对话记忆必须有用户消息 ID 和逐字引文。助手建议、无来源推断、虚构指标不能作为记忆来源。
- 已有职业线索可以复用原话索引。已确认画像、技能、简历经历、职业岗位和行动计划作为投影进入识海，原始业务数据仍由原工作台维护。
- 官方和自配连接都由服务端持久队列在回复结束后整理，使用本轮所选模型配置。关闭浏览器不影响整理；退出本机程序后暂停，重启可恢复。撤销外部模型授权后不再发起整理请求。前端只保留手动刷新入口，避免两边重复触发。
- `emotion` 仅是用户明确表达的短期语气线索。普通一次性情绪不自动长期保存，不生成心理或人格诊断。

## 主库和索引

仍使用同一份 `agent.sqlite`，通过幂等建表升级旧数据库：

| 表 | 用途 |
| --- | --- |
| memory_nodes | 记忆内容、类型、确认状态、修订号、提及和召回次数 |
| memory_sources | 原话、消息 ID、来源会话或已确认资料的版本标识 |
| memory_fts | FTS5 全文索引；英文词与中文二元词检索 |
| memory_links | 明确标记的冲突关系 |
| memory_recalls | 一轮回答实际选中的记忆、来源 ID 和召回理由 |
| memory_suppressions | 用户删除后阻止相同材料自动重建的哈希指纹 |
| memory_settings | 记录、参与回答和账号同步三个独立开关 |
| memory_jobs / memory_worker_meta | 后台整理任务、租约、去重、重试和启用时间 |
| memory_replica_keys | 不随改正文案改变的同步身份，删除后保留空引用 |
| memory_sync_clock / memory_sync_entries | 账号版本游标、当前摘要及不含正文的删除墓碑 |
| memory_sync_client / memory_sync_cursors | 各同步地址的已确认版本及断点 |

不手写 B+ 树，不另建 JSON 文件库。分类 Markdown 文档由主库即时生成，可查看或导出，不维护第二份事实副本。节点之间的“相关”关系来自共同词，只表示关联，不表示因果、胜任力或事实确认。

## 从问题到回答

1. 按账号过滤，以中文二元词和英文词进行 FTS5 检索，最多取 48 个索引结果；补充各分类近期或重要记忆，总候选不超过 80 条。
2. 先限制节点，再按消息 ID 校验来源，避免为少量记忆读取整段长对话。
3. 相关性清晰时直接使用本地排序；不足以判断或用户在问往事时，复用本轮所选聊天模型，从最多 36 个候选中选 ID。模型只能选择给定 ID，不能新增事实或执行工具。
4. 可选的相关性判断每轮至多一次，四秒后回退本地结果；格式不合法、接口失败或用户停止任务也会退出。没有模型下载、embedding 接口、第二套 Key 或独立模型配置。
5. 本地排序综合相关性、保留权重、置信度、重要度和用户降权，再使用 MMR 的词项版本减少重复内容：0.75 × 相关得分 − 0.25 × 与已选记忆的最高 Jaccard 相似度。
6. 排除归档、来源失效、相互冲突和已淡出到低频阈值的节点，最多选 8 段，正文及引文合计约 3500 字符。
7. 证据包进入实际领域上下文并计入上下文预算。保存召回记录，发布只含 ID 和数量的 `memory.recalled` 事件，前端点亮相应区域。

这是“检索证据 → 辅助生成”的 RAG 链路。聊天模型做的是候选相关性判断，不是向量计算；本地词项得分也不是岗位匹配率或录用概率。相关性判断需要时会增加一次小型模型请求；记忆提取与原有会话整理共用一次返回，不另发一次抽取请求。

MMR 参考 Carbonell 与 Goldstein 的原始工作：[The use of MMR, diversity-based reranking for reordering documents and producing summaries](https://doi.org/10.1145/290941.291025)。当前实现采用词项集合相似度，不声称使用了专用语义向量模型。

## 持久整理与恢复

- 队列按“对话 + 最新用户消息”去重；更新消息后取消尚未执行的旧整理任务。
- 用 SQLite 原子领取任务，租约 180 秒，失败最多尝试六次，带退避；耗尽或过期租约不会一直显示运行中。
- 回复已经保存但来不及入队时，启动恢复会检查本功能启用后的近期完成任务，不突然回扫用户全部历史。
- 主回复和工具执行优先，正在运行的对话先延后整理；撤销授权、归档或消息被替换后不保存过时结果。
- 保存记忆成功后再推进已整理消息标记，同一来源重复重试不增加提及次数。错误只保存统一提示，不保存上游响应或 Key。
- 识海状态反映后台队列；失败可点“重新整理”。管理员可用 `AGENT_MEMORY_BACKGROUND=false` 停用自动整理，默认开启。
- 目前整理器读取近期对话窗口，不做整份历史档案的离线回填；长时间模拟不能替代真实连续使用观察。

## 账号同步

- 复用现有 Cloud Hub 和 PC 主动连接，不新增独立服务。只有官方账号、有效且已绑定的设备、设备会话同步开启，以及识海“随官方账号同步”开启时，PC 才交换记忆。API-Key 本机身份不上传。
- Hub 声明 `memory_sync: 1` 后才启用新协议，旧云端跳过记忆同步并继续原会话链路。本地代码更新不代表已部署的云服务器也完成更新。
- PC 通常每 15 秒交换一次变更，每批最多 40 条和约 256 KiB；服务端增量拉取每页最多 100 条，并限制响应大小。后台整理后的新增内容也会进入后续同步。
- 同步键保持稳定，正文改正不改变身份。相同版本重发不会重复记忆或增加提及。召回次数属于各设备，不触发同步写入。
- 删除优先，使用无正文墓碑与来源哈希阻止离线旧设备恢复已遗忘内容。回退和删除原会话会撤销相应来源；其他独立证据仍保留。
- 不同设备基于旧版本同时改正时保留两种表述，并使用识海原有冲突核对入口；确认其中一条后另一条归档。请求在途时又有本机编辑，也不会被旧响应覆盖。
- 同步来源保留逐字引文、来源时间和原会话标识，并标注“已同步原话”；它不伪装成本机实际存在的会话外键。该证据来自已授权设备，不等于服务端重新审阅了源会话。
- 白名单协议拒绝任意配置字段，遮蔽联系方式、已登记密钥和常见本机路径。不传模型配置、设备密钥或模型内部续接状态。
- 云 Agent 与 Hub 共享同一用户主库时直接使用账号记忆。若单独部署云 Agent 到另一份数据库，需要接入同一同步链路，不会自动跨数据库读取。
- SQLite 同步事务支持嵌套保存点，来源、正文和同步游标一起提交或回退。当前验证覆盖正常重启与离线续传；异地灾难恢复和大规模多实例运行仍需要独立演练。

## 时间衰减与强化

采用可解释的指数半衰期，作为工程近似，不宣称精确复现人的艾宾浩斯曲线。

- 普通候选：基础半衰期 45 天。
- 计划：基础半衰期 14 天。
- 情绪线索：基础半衰期 2 天。
- 每次来自新用户原话的重复提及延长保留时间，最多计入 8 次强化。
- 已确认的职业事实保留权重至少为 0.8；长期锚点至少为 0.95。
- 情绪线索即使确认也仍然衰减。
- 模型召回只增加召回次数，绝不算作用户重复提及。
- 降权、归档或删除来自用户主动操作。衰减只降低召回权重，不自动物理删除事实。

## 纠正、冲突和删除

- 记忆变更用修订号阻止旧页面覆盖新内容。
- 模型可提出两段记忆可能冲突；冲突双方暂不参与回答，用户确认其中一条后另一条归档。
- 改正识海不会悄悄修改正式画像或简历，界面会明确说明。
- 纠正、归档、删除后，已保存召回中的旧引用同步失效。
- 回退对话分支会移除被替换消息产生的派生来源。
- 永久删除对话会清理该会话的派生来源；其他独立已确认资料继续保留。
- 永久删除记忆保留无正文的去重哈希，避免整理同一条旧消息时再次出现。原对话、正式简历与职业档案不会被连带删除。
- 联系方式会在识海投影中遮蔽；已登记模型密钥沿用统一脱敏。记忆不是用于存储口令的保险箱。

## HTTP 接口

- `GET /api/v1/agent/memory?conversation_id=&search=`：识海、分类计数、关系、文档及最近召回。
- `POST /api/v1/agent/memory/:id`：确认、改正、降权、归档、恢复、长期锚点或永久删除。
- `POST /api/v1/agent/memory/settings`：更新三个开关。
- `POST /api/v1/agent/memory/retry`：重新排队未完成的整理。
- `POST /api/v1/hub/worker/:id/memory`：同账号官方令牌 + 设备凭据校验后的增量交换。
- `GET /api/v1/agent/memory/export`：导出当前有效记忆的 Markdown 文档。

全部接口沿用本机/官方账号鉴权及同源保护；同步另外校验设备凭据与同步设置。小程序可从同账号 Hub 的记忆读取接口获取同步后的识海数据。本轮未自动更新远端服务器。

## 三维星云交互

- 星云通过三维噪声与光线步进生成云带和暗尘；背景计算纹理限制为不超过 800 × 540，再独立叠加清晰星尘与记忆星体。相机旋转会改变体积采样方向，不使用静态背景图片。
- 每个可点选星体对应一个真实记忆 ID；分类决定星群，ID 决定稳定位置，刷新或改正文案不会随机跳位。
- 支持鼠标拖动旋转、右键平移、滚轮/触控捏合缩放，提供重置及可暂停的自动环绕。
- 点选星体或投影文字会打开相同的来源详情；从右侧列表选择也会平滑推进镜头并展开相邻记忆；选中期间暂停自动环绕。分类和文字搜索会降低无关星体亮度。
- 全景从真实 related/conflict 关系提取连通骨架；选择记忆时补充该节点的关系并压暗无关连线。召回或聚焦时，仅沿这些真实关系显示流动光点。装饰星尘不可点选，不算用户记忆。
- 记忆衰减通过星体亮度呈现；长期锚点略微增大星体，选中星体显示小范围光环；中央不放大光圈。空库保留星云氛围，不编造人物记忆。
- 画布尺寸由 ResizeObserver 更新；限制像素密度和渲染帧率。最小化、离开视口、页面进入后台时暂停渲染，关闭时回收 WebGL 资源。
- 遵从系统减少动态效果和应用动画开关，关闭自动运动后仍可手动操作。WebGL 不可用时仍可通过右侧列表管理记忆。
- Three.js 随识海窗口异步加载，不进入主对话首屏。
