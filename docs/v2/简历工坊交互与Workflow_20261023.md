# 连续职业对话中的简历能力与后台 Workflow（2026-10-23 再修订）

## 为什么改

上一版的问题不是少几个圆角，而是把内部工作流直接做成了用户要填的五步表单。用户想要的是穗奈听懂零散叙述，慢慢追问，顺便教会自己判断什么值得写。本次撤掉材料表单和五步导航，不再让用户先准备完整资料和 JD。

**前台是对话教练，后台仍是有来源、有确认的简历工作流。** 不能仅把表单字段逐条变成气泡提问，也不能为了聊天顺滑而取消事实确认。

## 产品主线与展示方式

**认识自己 → 探索方向 → 明确技能缺口 → 学习与实践 → 反馈调整 → 按需准备求职材料。** 这些环节允许来回讨论，不要求用户先想清楚岗位；简历是求职阶段的中间产物，不是产品主线本身。

- 取消侧栏独立“简历工坊”入口。不再为了使用能力而查找、新建或切换专用对话。
- 新对话与旧对话都可在当前聊天按需使用职业和简历工具；旧 resume 标记只兼容既有数据，不再缩减成只能写简历的助手。
- 快捷需求只填入当前输入框，不自动发送；只有明确的“新建对话”按钮切到空白聊天，首次发送或导入资料时才真正建立会话。
- 事实小结和取舍需要本人核对时，在当前对话展示轻量确认入口。简历资料条可收起，收起不换对话。
- 工作台是按需打开的资料窗口；职业档案、岗位和成长行动保留。简历预览、身份信息、可选微调和文件交付在其中的“简历与经历”里查看。
- 现有真实对话、用户自定义标题和简历材料不做破坏性迁移。

## 穗奈怎样引导

每轮根据用户刚才说的内容调整，而不是固定题单：

1. 接住具体叙述，区分用户自己做的与团队做的。
2. 适时解释一个重要点，而非每轮硬塞知识或空泛夸奖。
3. 一次只问一个最有价值的问题，允许不知道、跳过、没有指标、没有目标 JD。
4. 有一两段足够具体的经历，或用户要求先看结果时，就先整理小结，不无限追问等资料齐全。
5. 小结待核对时解释为什么这样写，等用户确认；没有 JD 时做方向版，不谎称已完成岗位匹配。

例子：用户说“我们小组做了网站”，先问“你亲手负责什么”，解释个人贡献为何重要；用户说没有业务数据，就追问产出或验证方式，不诱导编增长率。

**这些是模型的引导策略，不是对任意第三方模型质量的保证。** 结构、引用和确认由程序约束；回应是否自然仍需要用实际模型体验、迭代。

## 真正的执行链

1. 在当前主聊天里表达需求，不为简历再开对话。旧版专用会话创建接口仅为已有数据与测试保留兼容，前端不再调用。
2. 用户自由输入，经现有聊天 API 和流式 Agent 执行，不新增另一套聊天服务。
3. read_resume_context 读取已记录材料，避免重复提问。
4. capture_resume_material 只保留当前用户消息或本对话导入 TXT / Markdown 中的逐字原句。经历、求职方向与招聘 JD 分开，写入前检查 context_version。收集不等于已确认。
5. 有资料时 prepare_resume_step(facts)，再 propose_resume_update 提交经历建议；不要求已有 JD。
6. 用户在对话小结上核对确认，程序才置 facts_confirmed。口头“对”不由模型解释成已完成程序确认。
7. 用户希望起草后提交经历取舍并由用户确认；没有 JD 时 requirements 必须为空，不能编造岗位依据。
8. 只改写已保留的已确认经历，返回校验后的 Resume JSON。模型提交后仍可自然解释，而不是被固定的窗口提示打断。
9. 本地补姓名与联系方式、同模板 A4 预览、用户确认版本后发布真实 HTML / JSON 文件。没有偷偷截断正文去制造一页。

主对话工具同时覆盖职业档案、简历和通用任务。模型指令要求仅在用户提出简历需求时写入简历材料；一轮内调用简历收集／整理工具后，程序拒绝通过终端、write_file、publish_file 或 request_export 绕过本人核对交付该轮文件。下一轮普通学习或文件任务不受旧简历标记限制。旧版内部 request_id 请求仍使用受限工具集，仅作兼容。

## 失败和修改

- 没连模型也能查看起始页和已保存资料。聊天需要已测试聊天能力的模型；资料收集、整理和真实文件任务还需要工具能力与外部模型授权。固定演示明确标注虚构、不是实际模型理解。
- 停止、超时、格式不符不会显示假完成。未完成的整理可以继续补充，或显式结束请求，不需要重新填一遍。
- 经历新增或改正后，相关事实建议和后续稿需要重新核对。改 JD 保留已确认事实，重新评估取舍和正文。原文及不可变草稿历史仍在。
- 前端与服务端均检查版本，旧结果不能覆盖新材料；暂未做历史回退 UI。
- 姓名 / 联系方式有未保存修改时，不允许导出旧版，先明确保存到排版。

## 数据与能力边界

- 目前是一份账号级简历草稿，不是完整长期事实知识库；多个对话不会各自拥有多份独立简历。
- 原文、待确认事实、已确认事实、岗位要求和最终文稿分离。逐字引用、结构校验和数字检查不能证明语义绝对真实；个人责任与技能仍需本人确认。
- 本地后填的姓名联系方式不出现在模型简历上下文中。但用户在聊天或旧简历原文中提供的信息会交给所选模型，应先去掉不愿外发的内容。
- 职业档案与简历草稿独立，不自动覆盖。档案读取可辅助建议，本轮正式收集来源限用户消息和导入文本；需要复用时粘贴相关原文。
- 暂无 PDF / Word 自动解析、招聘链接抓取、真实岗位库推荐、服务端 PDF 或 DOCX、公开分享和自动投递。
- PDF 仍通过浏览器打印保存；需检查真实分页，不能称为服务端 PDF 下载。

## 固定演示

“看看她怎么聊”展示虚构人物与预设回答，不调用模型、不理解自由输入、不保存真实档案。点击预设回答能依次看个人贡献、责任边界、没有数字怎么表达、岗位缺口及固定 A4 示例。真实输入框在演示期间不显示，避免用户把脚本当成真实理解。
