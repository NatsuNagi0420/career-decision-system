# 青穗集简历模板研究与选型

> 研究日期：2026-10-26
>
> 目的：为青穗集建立多模板、可实时预览、可局部修改、可导出且不虚构经历的简历系统。

## 结论

青穗集不应该先照搬某一个简历网站，也不应该把 ASu-skills 的 18 套 HTML 直接当成最终产品模板。更稳妥的做法是把外部项目拆成四类能力：

- **简历规范**：参考 Yale OCS、MIT CAPD，保证版式熟悉、可读、适合 ATS；
- **模板与排版**：参考 ASu-skills、RenderCV，建立确定性的 A4 渲染和分页检查；
- **实时编辑交互**：参考 Reactive Resume、OpenResume，实现预览同步、点击定位和局部编辑；
- **数据模型**：参考 JSON Resume，但在其上增加青穗集自己的事实来源、岗位证据和确认状态。

青穗集自己的差异点应该放在“穗奈通过对话提取事实，解释为什么这样写，并让用户只修改选中的内容”，而不是放在模板数量或装饰效果上。

## 从公开简历规范提炼出的硬规则

Yale OCS 把模板按普通、技术、创意、Common Good、近期毕业生、经验型校友、硕士、博士后等场景区分，并说明这些模板按 ATS 使用场景设计。这个分类比“所有人都用一张简历”更适合青穗集。

MIT CAPD 的建议与青穗集的默认模板方向一致：使用招聘方熟悉的格式；默认一页，但有丰富经历或高级学位时允许两页；正文不要小于约 10pt；页边距至少约 0.5 英寸；经历使用明确动作动词，并尽量说明怎样完成以及产生了什么可核验结果。

这些规则应由程序和模板保障，不能完全交给模型自由发挥：

- 默认先生成单栏 ATS 安全版；
- 只有内容确实超出可读范围，才建议两页；
- 不用技能进度条表达能力等级；
- 不用图标代替联系方式或关键文本；
- 不用图片截图代替可选择、可复制的 PDF 文本；
- 没有证据时使用定性结果或列出待补信息，不编造百分比、用户量、排名和技术栈；
- 视觉版可以有颜色和分栏，但必须明确提示其 ATS 风险，并保留 ATS 版出口。

## ASu-skills 应该怎样接入

ASu-skills 的价值不在于把 `/make-resume` 原样搬进青穗集，而在于把它的几个约束变成我们的产品能力。

### 1. `great-resume`：负责表达优化

采用“动作 → 系统能力 → 业务价值 → 结果证据 → 个人边界”的改写顺序。每个强主张都保留：

- 原始说法；
- 建议写法；
- 支撑它的事实 ID；
- 用户是否确认；
- 风险和待补证据。

### 2. `job-match`：负责岗位对齐

把 JD 拆成硬性要求、核心能力、加分项和约束，再逐项对照用户已确认事实。输出“已有证据、简历没写清、确实缺口”，不输出看似精确但无法解释的录用概率。

### 3. `make-resume`：负责模板渲染和交付

模板只改变布局和视觉 token，不重新生成事实和正文。用户切换模板时，已有内容、事实来源和岗位目标保持不变。

### 4. `page-balance-qa`：负责确定性排版检查

生成后检查真实 A4 分页、内容填充率、溢出、页间平衡、字体与行距、链接是否可识别、打印时是否隐藏工具栏，以及 PDF 是否保留文本层。模型只能提出压缩建议，不能悄悄删掉经历或把字号压到不可读。

## 第一批模板方案

不建议一开始接入全部 18 套 ASu 变体。先做 5 个模板家族，每个家族保留一个主模板和少量颜色、密度变体。

| 模板家族 | 适合用户 | 版式特征 | ATS 风险 | 参考方向 | 首批 |
|---|---|---|---|---|---|
| **清晰单栏** | 应届生、实习生、通用岗位 | 教育背景靠前，项目和经历按时间排列，单栏、细分割线、低装饰 | 低 | ASu 01 / 03、Yale 普通与技术模板、Reactive Resume 单栏 ATS 模板 | 是 |
| **技术项目** | 前端、后端、AI、数据、测试、工程 | 项目靠前；技术栈与个人贡献分开；支持仓库、Demo、部署结果 | 低到中 | ASu 03 / 10、Career-Agents 技术岗位模板、RenderCV 工程主题 | 是 |
| **研究学术** | 科研、研究生、算法、实验室、论文较多 | 教育、研究方向、论文和科研项目独立分区；黑白打印清晰；留白更充足 | 低 | ASu 17、RenderCV 学术主题、Yale GSAS/PhD 模板 | 是 |
| **经历密集** | 多段实习、工作经历、项目和证书较多 | 支持两页；统一时间轴；低优先级内容可压缩，但不通过缩小到不可读来强行单页 | 低到中 | ASu 06 / 08 / 16、Reactive Resume 两页模板 | 是 |
| **轻量视觉** | 设计、内容、运营、产品、作品集型岗位 | 轻双色、较强版式识别；仍保持真实文本和可复制链接；同时保留 ATS 导出 | 中到高 | ASu 11 / 12 / 15、Reactive Resume 视觉模板 | 是，作为可选 |

不建议第一批默认使用满宽深色头部、复杂卡片矩阵、技能雷达图、技能进度条和纯图标联系方式。它们容易占用版面，也会影响 ATS 解析和招聘者快速扫描。

## 模板元数据应先固定

每个模板不应只有一个 `id` 和一个名称，至少需要以下元数据：

```text
id
name
family
audience
section_order
density
page_policy
ats_level
supported_sections
supports_photo
supports_bilingual
style_tokens
source_reference
license_note
```

其中：

- `family` 表示布局家族，模板切换时可以保留用户选择；
- `page_policy` 区分单页优先、允许两页和学术多页；
- `ats_level` 用“低 / 中 / 高风险”表达解析风险，不伪装成精确分数；
- `supported_sections` 避免研究模板强行显示空的“实习经历”；
- `supports_photo` 必须是模板能力，不是全局默认；
- `source_reference` 和 `license_note` 让后续维护者知道设计来自哪里、是否可以分发。

## 生成和交互流程

用户仍然从对话开始，内部结构化流程如下：

```text
用户叙述 / 导入旧简历
        ↓
事实底库：原文、来源、确认状态
        ↓
目标岗位与 JD
        ↓
证据过滤：主展示 / 次展示 / 暂不使用
        ↓
ResumeDocument：结构化正文 + block_id + fact_ids
        ↓
选择模板：只改变布局，不改变正文
        ↓
A4 实时预览：已完成区块保持稳定
        ↓
点击或框选 block
        ↓
穗奈只改选中的 block，并显示前后差异
        ↓
分页与 ATS QA
        ↓
HTML / PDF / DOCX / JSON 交付
```

要支持“框选修改”，简历内容必须先有稳定的区块 ID。姓名、摘要、每个 section、每条经历、每个 bullet、技能组都要能被定位；每个区块还要保留 `fact_ids` 和修改历史。否则框选只能传一大段文字给模型，无法保证局部修改。

## 与当前项目的关系

当前项目已经具备：

- 三套基础模板配置；
- `ResumeState` 的事实、岗位目标、取舍和正文结构；
- 同源 HTML 预览和浏览器打印入口；
- 简历对话式 workflow 文档；
- 事实 ID 的初步约束。

当前还需要在正式开发前确认：

- 主流程是否统一使用同一份 `ResumeDocument`；
- `ResumeEntry` 和 bullet 是否增加稳定 ID；
- 现有三套配置如何迁移为上面的五个模板家族；
- `ResumePreview` 中写死的模板名称和编号如何改为模板元数据；
- 预览、PDF、DOCX 是否都使用同一个渲染器；
- 局部改写是否保存 diff、撤销和事实来源。

因此，下一步的开发顺序应是“先统一数据和模板元数据，再做模板渲染，最后做框选局部改写”，而不是先复制 18 张 HTML 页面。
