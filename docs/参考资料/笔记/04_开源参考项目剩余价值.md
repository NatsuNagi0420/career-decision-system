# 04 · 开源参考项目剩余价值

> 判定只用代码，不用五个项目的能力笔记，更不用它们的 README。唯一例外是 `参考开源项目/README.md`——它描述的是已删除的 v1（Vue/Android/Spring Boot），此处只作反面提醒，不作依据。v2 一侧的每条结论都指到具体机制或行号。

## 二、明确不该吸收

| 参考条目 | 为什么不该 |
|---|---|
| JobFit-AI 的 FAISS/Two-Tower/LightGBM 学习排序 | 808 行岗位、试点 10–15 人，没有行为标签；架构 §8 已定不引向量库。训练与维护成本远大于收益，且会把"为什么是这个岗"变成不可解释 |
| Compass 的 ATS 抓取、Career-Agents 的 job-automation、JobSync 的定时发现 | 站点条款/robots/账号风险；`PILOT_PROTOCOL.md` §四明令不自动投递。抓取器一上线，数据合规就从"授权说明"退化成默许 |
| Compass 的 Obsidian vault 当业务库、Career-Agents 的数百 Markdown Agent | 会丢掉事务、ownership 与"模型不写库"这条边界。13 条 `CapabilitySpec`（12 条面向学生）已覆盖闭环，多出来的只是体积 |
| Compass/Career-Agents/JobSync 的 MCP 多入口 | 现在只有一个 Web 客户端，开口等于凭空多一套鉴权与审计面。等真有外部助理要接，先只读 |
| MyOfferAgent 的 100 分 ATS、Career-Agents 的正则 readiness 分 | 虚假精确。`PILOT_PROTOCOL.md` §四已禁适合度分；v2 用 `matched_count` 与证据条数表达强弱，不给"你适合 78 分" |

## 四、已经榨完的部分

- **Compass**：确认门（原子认领、过期在 WHERE 内、终态按图判）、逐字引文与反查、状态分槽、评测纪律都已吸收，多处被加强。只剩校准、多采样、语义检索三件，而前两件缺标签。
- **MyOfferAgent**：代码拼装文档、数字白名单、SSE 帧都已吸收；真正剩的只有输入侧隔离与注入用例。
- **Career-Agents**：readiness 的字段化（coverage/provisional）已吸收；内容目录只取结构不取量。
- **JobSync**：确认式写入与任务/结果闭环已吸收；求职运营（投递追踪、导入导出）整块不在产品范围。
- **JobFit-AI**：分层思想与确定性 baseline 已吸收为关键词版；排序学与离线排序指标不做。

## 五、边界

- 许可证：Compass 与 JobFit-AI 本地无顶层 LICENSE，只借机制不拷代码。
- 工作类型硬门槛与向量召回现在做不了，不是技术债：808 行岗位没有采集日期与工作类型（`JOB_CATALOGUE_PIPELINE.md:441-443`），这两件都要排在新数据之后。
- 判定有时间戳（2026-09-21）：重跑前先看 `app/capabilities/registry.py` 与 `evals/scoring.py` 是否已变。
