# 40 个场景动作与触发方案

日期：2026-10-19。**全部40项均为待制作/待接入方案，不代表40段成品已存在。** 当前网页只有6段基于原画的动作曲线。

## 这40项的含义

40项是有具体情境、面部表情、手形、动作节拍与真实触发条件的“场景动作配方”。它们复用14类基础动势、12组表情和8类左右手形，不等于40个完全不同的全身骨架动作，也不要求生成40张整个人物图。

每项必须能从“手臂方向/手形、面部神态、目光、节拍”中看出至少两项差别；不能仅改名字或台词。待机与等待类本身应安静，不以乱动充数。

P0为首先落地的16项高频动作；P1补齐其余24项。素材按03/04文档先P0后P1在同一任务内制作，不因此要求用户反复上传。所有动作的程序关键帧与真实业务事件接入由Codex后续完成，Manus本轮负责可用补图和姿态预览。

左/右手始终指角色自身：L在画面右侧，R在画面左侧。下表手形列顺序为L/R。

## 共用演出约定（本项目设计目标）

- 单个强调动作约2–5秒，入场0.3–0.6秒，动作主体1–3秒，收尾0.5–0.8秒；按动作自然程度调整，表内不是物理标准。
- 明显手势要能在默认桌面尺寸看出：手从垂放到胸侧/肩侧，不能用不足几像素的位移冒充新动作。源像素幅度不等于最终屏幕幅度，最终按网页视觉验收。
- 面部与手臂有时序：先看向目标，再抬手，末端停顿，收手后看回用户。不要让整张脸跟身体一直同频正弦摇摆。
- 正在阅读结果时回到安静状态；同一事件只播放一次，合并流式token，不每输出一句就反复挥手。
- 错误、用户新输入、需要确认优先打断正在庆祝；等待不摆出成功表情。真实业务成功与动画成功是两回事。
- 文本聊天默认闭口；只有真实语音音量/时间标记才驱动说话开口，M04的短暂询问开口除外。
- 本清单中的判题、里程碑、在线进度等若尚无实际事件，保持待接入，不以台词关键词猜测并伪造结果。
