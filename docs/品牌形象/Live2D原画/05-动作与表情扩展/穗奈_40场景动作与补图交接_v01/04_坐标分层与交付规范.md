# 坐标、分层、替换与交付规范

## 两套尺寸各有用途

- 外观原图：input/appearance_original_v2_1440x2560.png，1440×2560，RGB。它锁定人物造型与画风，**不直接作为运行时坐标**。
- 当前实际工作画布：1536×1536，来源于工作ORA；人物位于画面中间窄带。当前运行时25个可见部件全部注册在这套坐标。
- 默认交付runtime_png里的所有部件都是1536×1536、sRGB、8bit RGBA、透明背景，左上角(0,0)，不得裁切、拉伸人物或重新居中。大量透明区是正常的。
- input/base_layers_cropped是运行时透明边裁切版本，bounds定义见base_manifest_1536.json。input/base_layers_aligned是本包按bounds还原的全画布版本，给Manus直接叠图；两者必须逐像素等效。**裁切小PNG的局部(0,0)不是人物全画布(0,0)。**
- guides中的坐标网格、文字、十字和放大图只供参考；不能导入为可见人物层，也不能画进交付部件。

## 左右与手腕对位

| 标识 | 意义 | 原图腕部登记点 | 重叠检查区(x0,y0,x1,y1) |
| --- | --- | --- | --- |
| L | 角色自身左，画面右 | (946,730) | (926,722,968,746) |
| R | 角色自身右，画面左 | (570,730) | (546,722,589,746) |

这些登记点根据当前原臂腕部Alpha宽度制定，必须用实际合成接缝复核，不是手部3D骨骼标准。当前原型近似动画旋转点L(938,738)/R(568,738)不与登记点强行混为同一个点；后续运行时通过manifest显式转换。手形都在垂臂姿态的腕部坐标画，动作抬手在代码里完成。

每只手保留约12–24个源像素的腕部重叠带作为本项目目标范围，服从实际原腕宽与可见皮肤，不机械画成长条。新增手不能连衣袖、脸颊、道具背景或另一只手。

## 源工程与运行PNG各交一份

本次素材交付不是正式建模交付。source/suinai_extensions_v01.ora为首选可编辑源，包含原基准及新增部件的清晰分组；能制作真正分层PSD可同时提供。若工具无法制作ORA/PSD，不许改扩展名伪装：交全画布透明PNG＋manifest＋逐项状态，明确source_project缺失。已完成PNG仍应交付。

建议图层/组路径：

```text
BASE/reference_original_hidden        # 参考原图默认隐藏，不能作为补洞兜底层
BASE/current_layers/...              # 保留原25层，只读参考或完整存档
FACE/F01/face_skin                   # 干净脸底，不含新五官/眼镜/头发
EYES/V02/L/eye_white
EYES/V02/L/iris_with_highlight
EYES/V02/L/upper_lid_lashes
EYES/V02/L/lower_lid
EYES/V04/L/closed_lid_lashes          # 闭眼变体不显示其他眼内层
BROWS/B05/L
MOUTHS/M05/mouth_inner
MOUTHS/M05/lip_edge
ARMS/ARM01/L/arm_without_hand
HANDS/H02/L/hand_skin
PROPS/P01/pen
```

同一张画布上的不同眼眉嘴/手形是**互斥图层**，必须分别隐藏/显示。不是把它们平铺在一张PNG，也不是要求它们同时显示且不重叠。一个部件占一个透明图层/文件，处于相同原图坐标就不存在“布局冲突”。

运行时合成PNG按catalog/assets_requested.json的runtimeFile保存。例如runtime_png/V02_L.png是一只柔和眼的合成，眼白/虹膜/眼睑在源工程里仍独立；runtime_png/H02_L.png只有手和腕部重叠。若某些源层为空或不需要，不导出假的空白图凑数。

## 新旧部件的替换与层序

| 新逻辑组 | 必须关闭的旧层 | 合成说明 |
| --- | --- | --- |
| F01 | face、face_base_repair_patch | 新脸底在头发和五官之后；原鼻nose按源层单独保留，不烘焙第二个鼻子 |
| Vxx_L/R | 同侧eyewhite、irides、eyelash | 同一侧最多显示一个完整眼型；眼白→虹膜→眼睑，外眼角位置固定 |
| Bxx_L/R | 同侧eyebrow | 先去旧眉再加新眉，不要双眉 |
| Mxx | mouth | 先去原嘴；可见口腔在唇缘后，不能在旧嘴上开黑洞 |
| ARM01_L/R + Hxx_L/R | 同侧handwear整层 | 替换臂不含旧手，手腕接在同坐标；不能残留第六根手指或两只手 |
| P01/P02 | 无 | 道具不烘焙在手里；笔可以拆可见前段/被手指遮挡段 |

原眼镜eyewear仍独立显示；不把镜框或镜片重画到每个表情。把旧工程的“不理想但可见外观”直接作所有底层兜底会留下双五官，验收必须分别关闭旧层检查。

本轮不重新排列或覆盖工作区原文件，所有交付写入新的结果目录。后续新脸/新眼与刘海局部遮挡需要检查时，只改必要蒙版/补画区，列出被动过的区域；不能静默重生成整张脸来遮住误差。

预览允许裁切和放大，但需写出裁切框与倍率，附透明/浅色/深色背景检查。预览文件不满足runtime_png的同画布约束；这两类文件不要混用。

**delivery_manifest必须逐项列出全部53个请求ID。** 已完成用status=completed，无法交付用status=missing并写reason，未处理可用deferred并写reason。completed条目必须有真实文件、非空Alpha、实际bounds与sourceLayers；不要把“planned”写成“completed”。参考examples/delivery_manifest.template.json；模板本身所有项均为missing，绝不是可提交的成品清单。

manifest另记录sourceProject（null时报告缺失）、colorSpace、workingCanvas与baseSourceSha256。每个asset记录path、canvas、实际Alpha边界bounds、side、attachPoint（手/臂需要）、sourceLayers、changedFromBase说明。props握持和手形遮挡可使用额外关系字段，不必伪造动画骨骼。

## 并非本轮的输出

此次不要求Manus交付.cmo3/.moc3/.motion3.json或配音，不接受把PNG改名为moc3。补图合格后再由Codex接入表情/手形、制作并调节40项动作；正式Cubism网格建模另需真实可编辑工程及实际编辑器验证。素材验收通过也不等于正式Live2D模型完成。
