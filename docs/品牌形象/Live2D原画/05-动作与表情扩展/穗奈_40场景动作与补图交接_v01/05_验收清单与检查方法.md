# 补图验收清单与检查方法

## 必须交的证据

1. 新增部件实际文件＋可编辑源/PNG替代交付＋完整delivery_manifest；不是只有README、提示词或效果截图。
2. 中性重组：在1536坐标下从真实部件合成，与提交预览一致；原画参考层完全隐藏，不能铺整图补洞。
3. 12组戴原眼镜的脸部预览：各E编号逐一标注眼、眉、嘴组合，局部100%和适当放大各看一次。没有眼型时不能伪造E06开心笑眼等完成状态。
4. 16只手的局部预览：原臂+新手同坐标接合，指头结构正确；另在招手、思考、讲解、双手反馈四种现有关键姿态下检查掌面方向。
5. 关闭旧五官后的脸底、关闭头发眼镜后的脸底、去掉旧手的双臂、手腕接缝、三种背景边缘图。
6. DELIVERY_REPORT中按完成、部分、未完成列事实；如果少一项P1，不取消已完成的P0，不把缺项写成成功，也不只返回一段停止解释。

## 视觉验收（必须人工看）

| 检查 | 通过目标 | 常见不合格 |
| --- | --- | --- |
| 身份稳定 | 同一成年人物、脸型眼距发型镜框一致 | 生成了另一张更幼态或不同风格的脸 |
| 神态可读 | 温柔/专注/思考/认可/关切不靠台词也可区分 | 只动眉毛1px，12张全一样；全套都是默认笑 |
| 表情组合 | 眼眉嘴有协调关系 | 担心眉配大笑口、专注眉变成愤怒眉 |
| 脸底可替换 | 旧眼眉嘴无残影；预定露出区无固定发影 | 灰色遮罩盖住原眼，额头仍嵌一块刘海 |
| 原眼镜 | 独立保留、镜框线条与眼部不冲突 | 每张脸画一副镜框、叠出两副眼镜 |
| 手部结构 | 指头归属合理、左右匹配、掌形清楚 | 六指、拇指方向反、手背冒充正掌 |
| 腕部接缝 | 同肤色同粗细、不出现旧手残留 | 一臂两手、腕部细线断开、皮肤方块盖袖子 |
| 大动作姿态 | 肩缝连续、肘不尖折、掌向合理 | 抬臂后脱肩、手反向折、袖子纹理被严重拉碎 |
| 透明边 | 深浅背景均无白边或底色 | 黑白棋盘被烘焙进图、整画布Alpha=255 |
| 真实分层 | 独立关闭层能只移走那一个部件 | 每层都是同一张整人物、只改文件名 |

这些是本项目的美术目标，不是程序能自动判定的事实。几何脚本通过不代表好看、没有六指或适合正式Live2D。

## 本包自动检查工具

本包提供tools/validate_delivery.py，依赖Python与Pillow。Manus有工具条件时在自己的环境运行；用户只需把结果ZIP带回本地，Codex可以代运行。不要执行回传包里不明来源的脚本。

```text
python tools/validate_delivery.py /path/to/suinai_extensions_v01 --out /path/to/qa
```

工具检查：清单ID完整/唯一、请求路径匹配、completed文件真实存在、PNG为1536×1536 RGBA且Alpha非空并有透明区、实际bounds与登记一致、左右手attachPoint及腕部接触、未完成项确实列出、路径不越界。输出machine_report.json和本机实际完成部件的contact_sheet.jpg。

它不验证PSD/ORA能否在原生编辑器编辑、不验证闭眼好看、不验证握笔接触合理、不验证Cubism模型。sourceProject检查登记文件存在，以及ORA的基础ZIP/XML/画布结构或PSD文件头；不代替原生编辑器验证图层可用性。原生工程和视觉重组仍需独立验收。

退出码0=所有请求部件与要求的预览均通过结构检查；退出码2=部分交付或检查失败。**部分交付仍应打包，不因退出码2丢弃已完成素材。**

## 测试一份成品时的顺序

先跑结构检查 → 从实际部件重组中性脸和三组差异最大的表情 → 把手接回替换臂 → 用现有大动作看四种关键姿势 → 最后才把更多动作接入界面。严禁跳过换手去旧手、换眼去旧眼，只凭成品预览判断层可以用。

## 40项动作后续验收

- 本轮只是确定40个配方和补图标准。素材回来后，要逐项做“真实场景触发→进场→面部/手部配合→保持/收尾”的实际运行。
- 至少在默认桌面、窄屏、暂停回看、减少动态、错误打断与重复事件时验证。原六动作的浏览器测试是现状参考，不覆盖未来40项。
- 没有真实业务完成、没有题目判定、没有导出文件时不能播放相应成功动作。
