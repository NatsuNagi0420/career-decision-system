## 结论先说

**相比上一版有实质修复，可以保留并进入本地受控动作试装；但不是所有素材和动作都已正式通过。暂不建议再整包发回 Manus 反复重画。**

上一轮最重要的眼部分层错误已解决。手腕的静态断口也明显改善，但独立转腕仍需要本地绑定和接缝处理；“柔和/半睑/睁大”三个眼型并没有按原设想形成独立眼睑造型。建议先用合适的素材做三种自然反应，问题手型和可选道具暂缓，不让它们拖住产品推进。

## 2. 仍需注意：不要把文件齐全等同于表情齐全

### 眼型的区分不足，且“思考眼”不是自然侧目

这部分是可核实的像素事实：

- **V02柔和眼 = V01原态眼**，左右均逐像素相同。
- V02、V03、V06的眼白及上下眼睑分别完全相同，并没有真的生成柔和眼、半睑专注眼和略睁大眼的不同眼睑造型。
- V03只是将角色左眼虹膜向画面左移2像素、右眼虹膜向画面右移2像素，即相向移动；这不是双眼一起向一侧看。不能直接把该状态当作自然侧目思考。
- V06仅将虹膜上移1像素，并不是睁大眼。

**本地接入策略：** 先使用正常开眼、自然闭眼、笑眼三类，视线由程序基于同一目标点控制两眼，显式应用遮罩；不要把这些重复或仅移瞳孔的状态宣传成六种不同眼型。半睑与睁大若后续确实需要，再做局部眼睑补画或合适变形，不重新生成整脸。

### 静态手腕改善了，但还不等于可独立转腕

![上排v02、下排v03的同坐标手腕对照](D:/Project/career-decision-system/logs/suinai-extensions-v03-review-20261019/evidence/hands-before-after.jpg)

静态上，之前很明显的方形断边和大缺口已有改善；ARM01+H01仍可逐像素还原原臂。但新H02–H08全部从y=730才开始，ARM01仅到y=730，**新手与原臂只有1行像素搭接**，没有原先要求的约12–24像素隐藏重叠带；原H01为13行搭接。

我进一步固定前臂、只绕登记腕点转手±20°，H02/H04/H07等会露出楔形裂口。**原H01在同样的简单刚体转法下也会露缝**，所以不能把这全归咎于新图，更不能承诺“再生成手图就自动修好”。这项测试指出的是需要连续绑定、变形/蒙版与隐藏皮肤延展的地方，不代表现有网页动作已经回归失败，也不能据此要求单个PNG独自解决关节运动。

[独立转腕诊断图（固定前臂，非正式动作）](D:/Project/career-decision-system/logs/suinai-extensions-v03-review-20261019/evidence/independent-wrist-rotation.jpg)

美术观察：新腕部仍有轻微轮廓凸起；H07点赞的拇指与腕部过渡尤其不自然、点赞读感弱。这是本次视觉判断，不能只靠无透明断行就判美术通过。**H07暂不纳入首批动作**，鼓励可以先用H06轻握拳配笑眼/点头。H08没有可靠道具夹持，也先不做写字动作。

## 3. 包内有旧预览，不能当v03动作通过证据

四张`contact_greeting/thinking/responding/success.png`与上一版逐字节相同。它们可以保留作历史图，但不能作为这次新手腕或新表情已经在四种动作中通过的证据。应以后续从v03部件实际运行产生的帧为准，不依据旧图判断本次修复。

这不是“没有成果”：本轮新表情预览可独立重建，眼部源层确实改对。只是部分遗留文件未清楚区分新旧，验收必须分开。

## 4. 下一步：把精力转向本地动作，而非再次整包补图

1. **在隔离预览里接入，不覆盖现有角色资产。** 先导入合格源层，建立新旧五官/双手的互斥替换规则，重置不合理的预置双眼偏移。
2. **解决共同的腕部绑定问题。** 基于原像素补隐藏重叠带，采用连续网格或正确的遮罩/连接策略，验证手随前臂和独立转腕的不同情况；不能靠复制整手位移或硬接两个旋转图块。
3. **只先打磨三种完整反应：招手、思考、鼓励。** 候选手型H02/H05/H06，脸部先使用可辨识的开眼、闭眼、笑眼，配合视线、眉嘴、头部和身体节奏。H07、H08及道具先暂缓。
4. 三种在实际播放、暂停回放、动作打断和减少动态下稳定后，再复用基础动作扩展原40个场景。不要把未解决的接缝复制40次。
5. 后续将动作接到画像、岗位推荐、练习与简历导出的真实业务事件，而不是仅看到“完成”字样就播放成功。

当前不需要用户重新提交整套图片。若后续确实需要局部补画，给出已验证的单项缺口再发，不再泛泛要求“整体再精修一轮”。
