# 2026-10-19 手掌朝向修正

## 问题与范围

用户指出招手、托手时拇指和掌心像装反了。本轮对照原始 ZIP、同姿态截图及两侧开掌，确认不是整条胳膊旋转符号错误，而是三张手掌素材的左右手侧别与目标手臂不匹配：

| 素材 | 处理 | 是否影响原始 ZIP |
|---|---|---|
| H02_L（角色左手招手） | 修正手掌侧别 | 否 |
| H02_R（角色右手招手） | 同样修正；增加对称校准姿态检查，当前40场景没有新增右手招手场景 | 否 |
| H03_R（角色右手托掌） | 修正拇指侧别；所有复用它的场景一起生效 | 否 |
| H03_L 及 H01/H04/H05/H06 | 保持原样，不做全局左右翻转 | 否 |

L/R **均指角色自身**：L 在画面右侧，R 在画面左侧。不同手形可呈现掌侧、手背或侧面，不能根据拇指位于画面哪边就无差别翻转整套素材。

## 诚实边界

- 前一轮自动化只检查位移、腕点像素和网格连接，**没有证明手掌解剖朝向正确**；本轮补上指定开掌的人工方向基准与真实像素检查。
- 自动化不是通用人体解剖评分器；指向、思考、握拳额外保存截图进行目视复核，不宣称任意角度或所有手形完美。
- 修复的是已有Canvas动作预演与后续PSD输入，不等于已经创建原生 `.cmo3` / `.moc3`。不改变此前的原生模型制作状态。
- 回归开发中曾因全透明像素隐藏RGB、手绘指端点落在抗锯齿边缘导致测试误报；已分别按可见RGBA、有效不透明指端坐标处理。真实画幅裁切缺陷则修正了渲染器，没有跳过该检查。
