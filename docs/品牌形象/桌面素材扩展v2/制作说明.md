# 穗奈桌面素材扩展 v2

> **2026-10-16 · 最新方向更新**：用户已选择像素／点阵代码角色。下文插画出图方案保留为备用，不再是当前默认路线；当前已实现内容和验收见 [像素角色实现说明](像素角色实现说明.md)。


更新：2026-10-16。状态：**制作说明已完成；新增角色图尚未生成、尚未接入页面。**

## 1. 先解决什么

保留现在的「求职成长桌面」和穗奈，不再推翻整站。缺的是能配合用户行动的素材，而不是再做很多相似的微笑头像。

建议顺序：**确认同一角色与画法 → 先做一张拿手账的主姿势 → 验证页面效果 → 扩展动作 → 最后考虑动画。**

本轮没有调用出图 API、没有产生新立绘、没有改动页面或后端。当前会话未提供内置出图工具；如需备用 CLI/API 出图，须另外明确选择该方式，并配置相应 API 密钥。不要在聊天或设计文档中填写密钥。

## 2. 现有素材：数量不等于独立设计数

来源：`docs/品牌形象/`，盘点脚本：`web/scripts/brand-inventory.py`。

| 现有资产 | 独立设计数 | 当前价值与缺口 |
| --- | ---: | --- |
| 默认微笑、认真思考、完成后的开心、专注倾听、温和讲解、轻度担心、重要提醒、鼓励行动 | 8 | 可继续做头像和表情参考；很多图姿势与面部变化接近，难承担完整场景反馈 |
| 标准头像、主立绘、正面、侧面、背面 | 5 | 已有角色基准，不必重做三视图；新动作应沿用同一角色 |
| 品牌字图、组合 Logo | 2 | 不是动作素材，字标不交给图像模型生成 |
| 合计 | 15 | 各有原图与 BgSub 处理版，共 30 个 PNG；不是 30 套设计 |

`web/public/brand/desktop/` 中的 8 张 WebP 来自现有表情图裁切和缩放，**不是 8 张新画**。

### 不只缺图片，也缺使用规则

- 当前桌面陪伴窗口只在 `smile / think / listen` 间切换，已有素材尚未在该窗口充分使用；消息时间线另有自己的表情映射。
- 新图不能只随「打开哪个页面」切换为成功表情，必须对应真实状态；草稿生成不等于资料保存，也不等于找到工作。
- 现有 WebP 会逐张按透明边界裁切，尺寸不统一；新一组动作必须统一画布与定位，否则切换时人物会跳动。
- 部分现有图片可见白色外描边；新图先在浅紫、白色、深色底上检查边缘，不要默认把白边当透明。
- 40px 聊天头像应使用独立头肩裁切，而不是把整张半身图缩进去。裁切只解决可读性，不计为新设计。

## 3. 角色和画法锁定

### 参考文件的用途

1. **脸部与画法参考**：`docs/品牌形象/BgSub_默认微笑.png`。
2. **服装与整体比例参考**：`docs/品牌形象/BgSub_穗奈正面图.png`。
3. 已有标准头像、侧面与背面只作补充，不混用多张参考重新拼出一张新脸。
4. 角色素材在仓库中存在，不等于已完成权利核验。对外发布前保留原始制作记录、工具及授权信息。

### 必须保留

- 成年大学生的年龄感，平等、清醒的同伴气质；不是幼童、偶像或全知导师。
- 明亮栗棕中长发、琥珀色眼睛、**细银色圆框眼镜**。
- 麦穗发夹的位置与方向跟随正面参考：正面观看时位于画面右侧。不要镜像来回换边。
- 浅天蓝开衫、象牙白内搭；画到下半身时沿用海军蓝百褶裙和原鞋袜，不增加一套新服装。
- 原有二维动漫线稿与清晰色块，减少细碎高光和装饰，不另换画师式画法。

### 适配桌面的方式（设计建议）

**复古的是桌面和控件，穗奈继续保留清晰二维插画。** 不把整个人物强行像素化，也不通过改成紫头发、紫衣服去适配浅紫背景。主要靠统一轮廓、背景留白、动作和道具融入页面。

- UI 配色从 `web/src/desktop.css` 读取；不要另开一套品牌色。
- 角色图透明交付，不把窗口、按钮、桌面壁纸、文案画进人物图片。
- 手账使用统一的小型青绿封面和浅麦色索引；不添加文字或未经确认的精细 Logo。
- 小道具服务操作含义：手账＝记录，资料卡＝审阅，文件夹＝归档。不要同时塞进一堆道具。

## 4. 首批动作：六张，有先后顺序

下面均为**拟新增素材和拟接入状态**，不是已经实现的功能。

| 顺序 / 文件名 | 动作 | 拟使用位置或状态 | 需要避免 |
| --- | --- | --- | --- |
| A1 `suinai-journal-v2.png` | 拿打开的手账，另一手执笔，抬眼与用户交流 | 桌面默认陪伴、欢迎 | 脸被书挡住；像老师点名 |
| A2 `suinai-listen-v2.png` | 自然倾身、双手扶住手账、认真倾听 | 用户补充经历、等待用户继续 | 催促、委屈或依赖表情 |
| A3 `suinai-think-v2.png` | 低头查看手账中的几张便签，略带思考 | 真实任务处理中 | 伪装进度；一直循环说话 |
| A4 `suinai-compare-v2.png` | 并列展示两张无字资料卡，温和讲解 | 已有岗位对照结果或缺口说明 | 指定唯一正确职业；画百分比 |
| A5 `suinai-review-v2.png` | 将一张无字资料页递向用户、另一手稳住手账 | 等待用户确认资料或简历 | 擅自盖章；未确认就画完成 |
| A6 `suinai-filed-v2.png` | 把一张无字纸页放入文件夹，轻松微笑 | 服务端已确认保存或归档成功后 | 把草稿生成或录用当成已完成 |

**先只制作 A1 一张。** 只有脸、服装、手部、透明边缘和页面缩小预览都合格，再沿用这一张扩展 A2–A6。六张不必一次性全部出图。

## 5. 第二批与暂缓项

### 第二批：四张小尺寸空状态插画

同一人物的简化小插画，分别用于档案空白、暂无岗位对照、暂无学习计划、暂无简历。先沿用原比例简化，不同时开一套 Q 版新角色。

如确实选择 Q 版，先单独确认一张标准稿；不能将标准成年角色比例和 Q 版比例在同一个角色窗口里随机切换。

### 暂缓

- 换装、节日皮肤、房间 CG、大量全身立绘、剧情结局图。
- Live2D 拆件和复杂骨骼绑定；它们不能由一张 PNG 自动得到。
- 连续口型和自动说话动画；当前交互并没有稳定的语音同步依据。
- 好感度、压力值、惩罚表情、用户离开后失落等依赖性反馈。

等静态图统一后，可为同一基础姿势补一张闭眼帧做轻微眨眼；闭眼帧必须保持像素对齐，不能整个人重新生成。

## 6. 交付与验收

### 人物主图

- 母稿建议：1024×1280 的 RGBA PNG；如果工具不支持该尺寸，使用其支持的竖版尺寸，后期等比放入统一画布，禁止拉伸。
- 一张图片只含一个角色、一个动作。不要让模型先拼九宫格再切图。
- A1–A6 使用同一画布。以第一张定稿的人脸大小、眼线和人物中心为锚点，后续只改变必要动作；可在透明边界留空间。
- 头顶、眼镜、发夹、手和道具不得被画布裁断；下缘允许统一的半身裁切，不从手腕或道具中间截断。
- 不逐张 tight-crop，不给每张图自动重新居中，不为适配画框放大某一张脸。
- 必须是真正透明背景；棋盘格画在图里不算透明。
- 无文字、水印、窗框、背景场景或烘焙阴影。没有可编辑分层就标注「平面合成图」，不能交付为假 PSD。

### 页面衍生版本（不是新设计）

- 陪伴窗口：同画布 WebP，检查实际 276px 窗口下的表现。
- 聊天头像：从对应角色图人工确认统一裁切框后输出 128×128 / 256×256；检查 40px 下的眼镜、眼睛和发夹。
- 空状态：512×512 透明母稿，检查 96px 下轮廓。
- 原 PNG 保留在新版本目录；上线产物另存，不覆盖 v1 源图。

### 每张图的检查清单

- [ ] 是同一个穗奈：眼镜、脸型、发色、眼睛、发夹侧别、服装结构一致。
- [ ] 道具和手部可信；可见手指、笔和纸页没有明显穿模或融合。
- [ ] 动作在小图下可读，不仅是换了嘴形。
- [ ] 切换前后头部不跳动；没有因画布变化改变缩放。
- [ ] 白色、浅紫和深色背景下均无明显黑底、白边或残留棋盘。
- [ ] 页面上用于真实状态，无成功暗示或替用户决定的动作。
- [ ] 保留参考文件、最终提示词、制作工具、修改记录和使用权信息。

## 7. 规范冲突处理

旧的 `docs/VISUAL_STYLE.md` 描述了青色虚拟导师和「禁止紫色」；旧的 `docs/项目设计规范.md` 还描述早期 Vue/MD3 外观；原品牌稿保留了全身立绘优先和一套不适用于所有构图的负面词。这些不能直接混入本次出图。

当前 Web 的桌面外观以已经落地的 `web/src/desktop.css` 为实现依据；本文件只补充穗奈人物资产的规则，不替换隐私、无障碍和用户确认要求，也不修改 Android 设计。

新增半身图要使用本目录的分场景提示词；不能继续照搬旧稿把「半身像、近景」一律列为负面词。
