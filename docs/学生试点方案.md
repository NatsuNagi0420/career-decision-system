# 第一版学生试点方案

## 目标

验证学生是否能独立完成一次职业决策，并在随后一周继续执行计划。计划招募 10 至 15 名不同专业、不同年级的学生。

## 试用任务

1. 注册并完成基础引导。
2. 建立一个真实困惑对应的决策项目。
3. 保留 2 至 5 个候选，加入至少 2 个真实岗位样本。
4. 确认一个主目标和可选的备选目标。
5. 生成 2 至 4 周行动计划，并完成首个任务与成果记录。
6. 一周后提交首次复盘，决定保留、延期或跳过后续任务。

测试人员不得替学生填写结论，只记录卡点和理解偏差。AI 建议必须由学生本人确认后才能写入。

## 观察指标

| 指标 | 定义 |
| --- | --- |
| 目标确认率 | 建立项目后成功确认主目标的人数占比 |
| 首任务完成率 | 生成计划后 48 小时内完成至少一项任务的人数占比 |
| 成果记录率 | 完成任务时留下成果说明或链接的人数占比 |
| 首次复盘率 | 到下一周成功提交复盘的人数占比 |
| 次周继续率 | 复盘后仍有执行或调整行为的人数占比 |
| 关键卡点 | 需要工作人员解释、返回或放弃的具体步骤 |

## 访谈提纲

- 你最初想解决的职业问题是什么？系统是否准确保留了这个问题？
- 候选方向和真实岗位的区别是否清楚？
- 哪条证据最影响你的结论？哪条建议显得没有依据？
- 行动任务是否能在预计时间内完成？验收标准是否可判断？
- Android 今日页和 Web 决策页的分工是否自然？
- 一周后是什么促使或阻止你继续执行？

## 记录与隐私

- 使用测试账号或参与者主动提供的数据，不收集身份证号、精确住址等无关信息。
- 访谈记录使用参与者编号，不在 Agent 日志中写入姓名、联系方式、完整聊天或密钥。
- 单独记录设备、浏览器、网络和 `generationMode`，便于区分产品问题与模型降级。
- 试点结果保存在未公开的研究记录中；推送仓库前先移除联系方式和可识别信息。

## 完成标准

至少一名真实学生完成“决策 -> 首个任务 -> 次周复盘”；汇总 10 至 15 人的指标、主要卡点和下一版优先级。未实际发生的试用结果不得填写为完成。

匿名记录字段见 `docs/学生试点记录模板.md`。数据库量化指标使用 `scripts/report-pilot-metrics.ps1` 生成，并通过独立账号前缀排除 smoke、test 和 demo 数据；最终验收必须带 `-RequireAcceptance`。
