# 服创项目开发规范

> 面向参与本项目开发与维护的成员，用于统一代码风格、目录结构与协作流程，避免重复造轮子与“隐性约定”。

---

## 1. 目标与适用范围

- **目标**：保证前后端协作一致、功能链路可追溯、AI/数据调用可维护。
- **适用范围**：`frontend/`、`backend/`、`docs/` 全部仓内代码与文档。

---

## 2. 目录与模块约定

### 2.1 前端

- **入口**：`frontend/fr/src/main.ts`、`frontend/fr/src/App.vue`
- **路由**：`frontend/fr/src/router/index.ts`
- **API 封装**：`frontend/fr/src/api/*.ts`，统一经 `utils/request.ts`
- **页面**：`frontend/fr/src/pages/*.vue`
- **组件**：`frontend/fr/src/components/*.vue`
- **本地缓存**：`frontend/fr/src/utils/storage.ts`（career 相关统一 key）

### 2.2 后端

- **入口**：`backend/ba/src/main/java/com/example/ba/BaApplication.java`
- **Controller / Service / Mapper / DTO / VO / Utils**：按包结构归类，禁止跨层堆放
- **SQL**：`backend/ba/sql/schema.sql`

### 2.3 文档

- **维护性文档**：统一放在 `docs/`
- **功能链路**：新增功能必须同步更新 `功能链路帮助手册.md`
- **Bug 记录**：统一追加到 `bug.md`

---

## 3. 命名与结构规范

### 3.1 前端

- **页面组件**：`PascalCase`（如 `CapabilityProfile.vue`）
- **业务组件**：`PascalCase`（如 `AiAssistant.vue`）
- **API 文件**：小写 + 语义（如 `capability.ts`、`report.ts`）
- **路由路径**：使用短横线（如 `/capability-profile`）
- **样式**：全局样式在 `assets/global.css` 维护，组件内部尽量局部化

### 3.2 后端

- **Controller**：`XxxController`，一类业务一控制器
- **Service**：`XxxService` + `XxxServiceImpl`
- **Mapper**：`XxxMapper`，对应具体表
- **DTO/VO**：请求/响应严格区分，禁止复用实体类充当 DTO

---

## 4. API 与数据规范

### 4.1 接口调用

- **前端统一通过**：`frontend/fr/src/utils/request.ts`
- **API 前缀**：默认 `/api`，可通过 `VITE_API_BASE_URL` 覆盖
- **鉴权**：自动注入 `Authorization: Bearer <token>`

### 4.2 数据来源与权威性

- **目标岗位**：以 `/api/target-job/me` 为唯一权威来源
- **信息录入草稿**：前端本地缓存为主（`saveEntryDraft` / `loadEntryDraft`）
- **能力画像 / 路径规划**：由后端 AI 生成，异常必须有 fallback

### 4.3 统一返回结构（后端）

- `Result<T>`：`code` / `msg` / `data`
- 成功：`code=200`
- 失败：`Result.error(code, msg)`

---

## 5. AI 相关规范

- **模型调用集中**：统一封装于 `AiUtils`
- **结构化输出**：system prompt 明确字段与类型，避免非 JSON 内容
- **兜底策略**：AI 异常或 JSON 解析失败时必须返回 fallback 结构
- **日志**：可在 `AiUtils` 记录调试日志，但禁止泄露密钥

---

## 6. 本地缓存与状态管理

- **统一入口**：`frontend/fr/src/utils/storage.ts`
- **Key 统一**：`career.*` 前缀（如 `career.entryDraft`）
- **清空策略**：新增流程如需清空本地缓存，复用 `clearAllLocalCareerData`

---

## 7. 开发与调试约定

- **本地启动顺序**：MySQL → 后端 Spring Boot → 前端 Vite
- **常见问题排查**：
  - 401：鉴权/Token 缺失
  - JSON 解析失败：检查 AI 响应或 `JsonUtils`
  - 页面空白：先确认路由路径与本地缓存依赖

---

## 8. 代码提交与协作约定

- **提交信息**：简洁说明做了什么（如“修复路径规划页面空态”）
- **功能新增**：必须同步更新 `功能链路帮助手册.md`
- **修复 Bug**：必须同步追加 `bug.md` 记录
- **避免破坏**：修改公共工具（`request.ts` / `storage.ts` / `AiUtils`）需回归核心流程

---

## 9. 变更记录

- **新增规范**：请在本文件底部追加变更条目（日期 + 简述）

---

如需扩展，请保持章节结构清晰、条目简洁可执行。
