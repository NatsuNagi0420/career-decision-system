> Material Design 3、动态颜色与跨端主题规范

| 属性 | 内容 |
| --- | --- |
| 规范版本 | 1.1.0 |
| 更新日期 | 2026-07-12 |
| 适用范围 | Web、Android、共享设计 Token、主题偏好与背景资源 |
| 目标基线 | Google Material Design 3（Material You） |

## 1. 目的与约束级别

本规范是职业决策系统 Web 与 Android 的统一设计依据，用于约束视觉、组件、交互、响应式、动态颜色、自定义背景、无障碍和工程实现。设计稿、组件代码和业务页面不得各自维护另一套隐含规则。

本规范中的约束词含义如下：

- **必须**：不满足即不允许合并或发布。
- **禁止**：目标态中不得出现；迁移期例外必须登记。
- **应**：默认执行，偏离时必须说明原因。
- **可**：在不破坏其他规则时按场景选择。

截至 2026-07-12，Web 活动路由已经移除 Element Plus、旧主题变量和旧五步界面，统一使用项目 `M3*` 组件、Material Web 与 Material Color Utilities。Android 已接入项目 `M3*` 组件、Material Color Utilities、系统动态颜色和平台独立背景；账户级配色同步、云端背景资源、真机 Monet 与人工辅助技术验收仍属于后续工作，不能把代码迁移等同于整个跨端设计改造完成。

## 2. 官方基线与优先级

### 2.1 规范来源

出现冲突时，按以下优先级处理：

1. 本项目已经确认的产品需求、隐私和无障碍要求。
2. Google Material Design 3 官方规范。
3. Google Material Color Utilities 的动态颜色算法与颜色角色。
4. AndroidX Compose Material 3 的平台实现。
5. Google Material Web 的 Web 组件行为。
6. 本项目组件库的补充规则。

本项目不得使用 Material Design 2 的 MDC Web 作为新组件基础。M3 Expressive 的特殊形态、运动和组件变体不在 1.0 默认范围内；后续采用时必须升级设计规范版本并经过单独评审，不得与本规范静默混用。

### 2.2 技术基线

- Web 保留 Vue、Vue Router、Pinia、Vite、Axios 和现有业务 API。
- Web 已移除 `element-plus` 和 `@element-plus/icons-vue`，静态门禁禁止重新引入。
- Web 基础控件优先封装 Google `@material/web`；业务页面只能依赖项目级 `M3*` 组件，不得直接依赖底层第三方组件。
- Web 动态颜色必须使用 `@material/material-color-utilities` 或与其相同版本、相同输入和相同结果的官方实现。
- Android 必须使用 `androidx.compose.material3`，禁止在同一功能内混用 Material 2 组件。
- Android 系统动态颜色使用 Android 12 及以上系统能力；自选颜色和图片取色使用 Material Color Utilities 生成同源方案。
- 图标语义、尺寸、触控目标和状态必须遵循 M3。项目图标源统一使用 Lucide，禁止混用手绘 SVG、Emoji 和多套图标库。

### 2.3 版本锁定

当前锁定版本如下：

| 项目 | 锁定值 |
| --- | --- |
| Material Design 3 规范基线 | 2026-07-12 |
| `@material/web` | 2.4.1 |
| `@material/material-color-utilities` | 0.4.0 |
| Android Compose BOM | 2024.12.01 |
| AndroidX Compose Material 3 | 由 Compose BOM 管理 |
| `themeAlgorithmVersion` | `mcu-2021-v1` |

升级上述任一项目时，必须执行 Light、Dark、高对比度、Web、Android 的主题快照回归。不得因依赖升级使同一种子色在用户不知情时产生大幅变化。

## 3. 产品设计原则

### 3.1 任务优先

- 界面必须帮助学生快速判断“当前目标、当前状态、下一步做什么”。
- 工作台同一时间只突出一个主要行动。
- 决策依据、风险和不确定性必须比装饰性内容更醒目。
- AI 建议必须明确标记为建议，写入用户数据前必须确认。

### 3.2 安静而高效

- 本产品是需要反复使用的职业决策工具，不采用营销落地页式排版。
- 禁止使用渐变球、光斑、装饰性漂浮卡片、无业务含义的大面积插画。
- 禁止卡片嵌套卡片。页面分区优先采用无框布局、分隔线和 Surface 层级。
- 卡片只用于独立重复项、弹窗内容和确实需要边界的工具。
- 动态颜色不得把所有区域染成同一色相；中性 Surface 必须承担主要内容背景。

### 3.3 个性化服从可读性

- 自定义背景和 Monet 配色是可选增强，不得成为使用核心功能的前置条件。
- 背景图片不得直接承载密集表单、表格、任务列表和长文。
- 用户图片无法生成合格配色时，必须回退到默认主题，而不是强行使用低质量颜色。
- 用户必须始终可以恢复默认主题、移除背景和切换 Light/Dark。

## 4. 信息架构与自适应导航

### 4.1 Web 一级导航

Web 一级导航固定为：

```text
工作台 | 职业探索 | 决策项目 | 行动计划
```

用户菜单固定包含：

```text
个人档案 | 历史记录 | 设置 | 退出登录
```

必须遵守：

- 一级导航表达长期任务，不表达系统内部处理步骤。
- 禁止在全局顶部重新展示旧版“信息录入到报告生成”五步导航。
- 能力画像属于个人档案和决策证据。
- 报告属于决策快照和历史记录，不是一级导航或流程终点。
- “职业方向”和“招聘岗位”统一位于职业探索内部，但必须保持两个清晰层级。

### 4.2 决策项目内部阶段

五阶段导航只允许出现在决策项目工作区：

```text
明确问题 -> 整理证据 -> 收集候选 -> 对比验证 -> 确定目标
```

阶段导航必须表达已完成、当前、可访问和锁定状态。不得只依赖颜色区分状态；必须同时使用文字、图标或形状。

### 4.3 Android 底部导航

Android 固定为：

```text
今日 | 目标 | AI 导师 | 我的
```

Android 启动后的默认页面必须是“今日”。复杂候选比较和计划全局编辑应引导到 Web，不在小屏幕复制桌面工作区。

### 4.4 窗口尺寸类别

采用 M3 自适应窗口思想，Web 使用以下项目断点：

| 类别 | 宽度 | 主要导航 | 内容策略 |
| --- | ---: | --- | --- |
| Compact | `0-599px` | 底部 Navigation Bar | 单列、分步编辑、固定主要行动 |
| Medium | `600-839px` | Navigation Rail | 单列或窄双列，减少辅助信息 |
| Expanded | `840-1199px` | Navigation Rail 或标准 Drawer | 双列工作区、可见上下文面板 |
| Large | `1200px+` | 标准 Drawer 或 Rail | 受约束内容宽度，不无限拉伸 |

Top App Bar 用于品牌、页面上下文和全局操作，不得与 Rail、Drawer 或 Navigation Bar 重复渲染同一组一级入口。

## 5. Design Token 架构

### 5.1 Token 分层

所有样式必须从 Token 获取，分为三层：

```text
Reference Token -> System Token -> Component Token
```

- Reference Token：原始色阶、字体、尺寸和运动参数。
- System Token：`primary`、`surface`、`headlineMedium` 等语义角色。
- Component Token：某个组件在特定状态下对 System Token 的引用。

业务页面禁止直接引用 Reference Token。页面只允许使用 System Token 或项目组件。

### 5.2 命名

Web CSS 变量必须遵循：

```text
--md-ref-*
--md-sys-*
--md-comp-*
--career-sys-*
```

其中 `--career-sys-*` 只用于 M3 未内置的职业产品语义色和业务尺寸。禁止新增 `--blue-500`、`--page-card-color` 等缺乏层级的临时变量。

Android Token 名称必须与 Web 语义角色一一对应，例如 Web 的 `--md-sys-color-primary` 映射到 Compose `MaterialTheme.colorScheme.primary`。

### 5.3 单一事实来源

设计 Token 必须同时存在于：

```text
设计规范
机器可读 Token 文件
Web CSS Variables
Android Compose Theme 映射
设计工具 Variables
```

任何颜色、字体或形状变更必须先修改 Token 来源，再生成或同步到平台实现。禁止分别手改 Web 与 Android 的最终颜色值。

## 6. M3 颜色系统

### 6.1 必需颜色角色

每个主题必须完整提供以下角色：

| 角色组 | 必需角色 |
| --- | --- |
| Primary | `primary`、`onPrimary`、`primaryContainer`、`onPrimaryContainer`、`inversePrimary` |
| Secondary | `secondary`、`onSecondary`、`secondaryContainer`、`onSecondaryContainer` |
| Tertiary | `tertiary`、`onTertiary`、`tertiaryContainer`、`onTertiaryContainer` |
| Error | `error`、`onError`、`errorContainer`、`onErrorContainer` |
| Surface | `surface`、`onSurface`、`surfaceDim`、`surfaceBright` |
| Surface Container | `surfaceContainerLowest`、`surfaceContainerLow`、`surfaceContainer`、`surfaceContainerHigh`、`surfaceContainerHighest` |
| Variant | `onSurfaceVariant`、`outline`、`outlineVariant` |
| Inverse | `inverseSurface`、`inverseOnSurface` |
| Utility | `surfaceTint`、`shadow`、`scrim` |

旧的 `background`、`surfaceVariant` 等角色只可作为迁移别名，不得成为新组件唯一依赖。新组件优先使用 Surface Container 系列。

### 6.2 使用规则

- `primary` 只用于主要操作、当前状态和关键强调，不得铺满整个页面。
- `secondary` 用于次级操作和辅助筛选。
- `tertiary` 用于与主流程不同但同样重要的辅助信息。
- `error` 只表示错误、危险和破坏性操作，禁止用于普通提醒。
- 正文主要使用 `onSurface`，次要信息使用 `onSurfaceVariant`。
- 页面大背景使用 `surface` 或 `surfaceContainerLowest`。
- 同一区域的文字与图标必须使用对应的 `on*` 角色，不得凭视觉猜测颜色。
- 禁止在业务组件中直接写 `#RRGGBB`、`rgb()`、`hsl()` 或平台颜色常量。

### 6.3 扩展业务颜色

Material 3 没有内置 success、warning 和 info。项目必须通过 Material Color Utilities 创建并与主题色 harmonize 的扩展 Custom Color：

| 项目角色 | 用途 |
| --- | --- |
| `careerSuccess` / `onCareerSuccess` / `careerSuccessContainer` | 已完成、同步成功、验证通过 |
| `careerWarning` / `onCareerWarning` / `careerWarningContainer` | 延期、临近截止、证据不足 |
| `careerInfo` / `onCareerInfo` / `careerInfoContainer` | 中性说明、同步状态、AI 模式提示 |

任务状态不得只用颜色表达：

| 状态 | 颜色角色 | 必需辅助表达 |
| --- | --- | --- |
| `todo` | Surface/Outline | “待开始”文字和空心状态图标 |
| `in_progress` | Primary Container | “进行中”文字和进度图标 |
| `completed` | Success Container | “已完成”文字和完成图标 |
| `deferred` | Warning Container | “已延期”文字和新日期 |
| `skipped` | Surface Container High | “已跳过”文字和跳过图标 |

图表不得只使用 Primary 的连续浅深变化。分类图表必须使用可区分、可读且经过 harmonize 的扩展色板，并提供图例、标签或纹理辅助。

## 7. Monet 与动态颜色

### 7.1 名词

“Monet”在本项目中指基于来源颜色生成 Material 3 Tonal Palette 和语义 Color Scheme 的动态颜色能力。工程和用户界面优先使用“动态颜色”名称，避免把“取一个主色”误认为完整 Monet。

### 7.2 颜色来源

主题必须支持以下来源：

| `colorSource` | Web | Android |
| --- | --- | --- |
| `brand` | 默认品牌种子色 | 默认品牌种子色 |
| `system` | 跟随 Light/Dark，使用账户或品牌种子色 | Android 12+ 使用系统 Dynamic Color |
| `custom_seed` | 用户选择的种子色 | 用户选择的种子色 |
| `custom_image` | 用户选择图片并在本地取色 | 用户选择图片并在本地取色 |
| `account` | 使用账户共享颜色设置 | 使用账户共享颜色设置 |

Web 浏览器不能读取操作系统壁纸，禁止声称 Web 的“跟随系统”能够获得系统 Monet 壁纸颜色。

### 7.3 生成规则

- 默认动态方案采用 Material Color Utilities 的标准 Tonal Spot 方案。
- 输入必须归一化为 sRGB ARGB 种子色。
- 必须从同一种子色生成 Light 和 Dark，不得分别人工挑选两套主色。
- 默认对比度级别为 `0`；高对比度模式使用官方对比度能力，不得只把文字改为纯黑或纯白。
- 生成结果必须包含完整 M3 颜色角色和扩展业务颜色。
- Web 与 Android 使用相同的 `seedColor`、`schemeVariant`、`contrastLevel` 和 `themeAlgorithmVersion` 时，语义角色必须在允许的舍入差异内一致。
- 禁止人工修改某个生成角色来“看起来更好”。如结果不适合，应更换种子色或方案变体并重新生成。

### 7.4 图片取色流程

```text
选择图片
-> 校验类型和尺寸
-> 修正 EXIF 方向并移除元数据
-> 下采样
-> Material Color Utilities 量化与评分
-> 提供 1-4 个候选来源色
-> 生成 Light/Dark 预览
-> 对比度检查
-> 用户确认
```

必须遵守：

- 默认在客户端处理图片，不上传即可完成取色。
- 不得简单使用平均色或出现次数最多的单一像素色。
- 候选色必须经过 Material Color Utilities 的量化和评分。
- 候选色过暗、过亮、近灰或无法产生可读方案时，必须提供品牌色回退。
- 保存主题时只需保存种子色、方案和算法版本，不保存每一个生成色阶。
- 用户主动同步背景前，不得上传原图。
- 选择系统动态颜色时，设置页必须明确标注颜色来自 Android 系统壁纸，并隐藏不会影响系统 Monet 的应用种子色与对比度控件。
- 图片候选不得只展示单个色点；至少预览由该种子生成的 Light/Dark `primary`、`secondary`、`tertiary` 与 `surface` 角色。
- “仅应用配色”与“应用配色并设置背景”必须是两个明确动作；只取色时不得保留或上传原图，也不得覆盖现有 Android 背景。

### 7.5 主题模式

必须支持：

```text
Light | Dark | Follow system
```

主题切换不得重新加载页面，不得丢失表单草稿，不得造成主要布局位移。所有弹窗、Snackbar、图表和 Portal 内容必须与当前主题同步。

## 8. 自定义背景

### 8.1 背景与配色分离

背景图片与主题配色是两个独立概念：

- 背景可以不同但共享同一种子色。
- 背景可以相同但各平台使用不同主题模式。
- 删除背景不得删除账户主题配色。
- 更换 Web 背景不得覆盖 Android 背景。

### 8.2 背景作用范围

- 背景只渲染在应用 Page Canvas、登录页背景或允许个性化的留白区域。
- 表单、比较表、行动任务和历史详情必须位于不透明度足够的 M3 Surface 上。
- 禁止在复杂业务页面中把长文本直接叠加在高细节图片上。
- 背景不得替代错误、选中、禁用等组件状态。
- 背景不得引入自动播放视频、GIF 或高频动画。

### 8.3 渲染层级

从后到前固定为：

```text
Background Image
-> Scrim
-> Page Canvas Tint
-> Surface Containers
-> Content and Components
```

Scrim 必须使用 `scrim` 语义角色。系统应自动设置满足对比度的最低遮罩强度；用户可以增加遮罩，但不得降低到不合格水平。

### 8.4 图片要求

- 支持 JPEG、PNG 和 WebP。
- 禁止 SVG、GIF、远程热链和无法验证来源的脚本化格式。
- 原始文件建议不超过 10MB；显示前必须生成适合目标设备的派生图。
- 必须支持裁剪焦点 `focalX/focalY`，避免响应式裁剪切掉主体。
- 上传前必须移除 GPS、相机和时间等 EXIF 隐私信息。
- 云端同步图片必须存入对象存储；禁止将 Base64 或 BLOB 写入 MySQL。
- 删除背景时必须同时删除不再被引用的云端资源。

### 8.5 性能与失败回退

- 背景不得阻塞工作台主要数据渲染。
- 加载时先显示当前主题的 Surface，不显示白屏或布局抖动。
- 图片加载失败时回退到纯色 Surface，并保留已生成的主题。
- Compact 设备应使用尺寸更小的派生图，禁止直接下载桌面原图。
- 用户开启节省流量或减少数据使用时，可不加载云端背景。

## 9. 跨设备主题与背景同步

### 9.1 分层模型

主题偏好必须分层保存：

```text
shared   账户共享配色
web      Web 平台偏好与背景
android  Android 平台偏好与背景
device   当前设备本地覆盖，不上传
```

生效优先级：

```text
device > platform(web/android) > shared > system/brand default
```

### 9.2 默认行为

- 账户配色默认可跨端共享。
- Web 与 Android 背景默认独立。
- 背景同步必须由用户显式开启。
- 用户可只同步图片生成的 `seedColor`，而不上传图片本身。
- Android 选择“跟随系统动态颜色”时，本机系统方案优先于账户配色，但不得修改账户共享配置。

### 9.3 逻辑数据契约

每个主题偏好至少包含：

```text
scope
themeMode
colorSource
seedColor
schemeVariant
contrastLevel
themeAlgorithmVersion
backgroundAssetId
backgroundEnabled
focalX
focalY
scrimLevel
version
updatedAt
```

背景资源与主题偏好必须分表或分资源管理。并发更新使用版本号或 ETag；禁止使用一个全局 `backgroundUrl` 做最后写入者覆盖。

## 10. Typography

### 10.1 字体族

- 中文优先使用 `Noto Sans SC`，其次使用系统无衬线中文字体。
- 拉丁字符和数字优先使用 Roboto，无法加载时使用系统无衬线字体。
- 禁止使用未获得授权的 Google Sans。
- 数据、代码、请求编号和时间戳可使用等宽字体，但不得用于正文。
- 中文界面的 `letter-spacing` 固定为 `0`，这是针对 CJK 可读性的本地化规则。

### 10.2 M3 Type Scale

| Token | 字号/行高 | 建议字重 | 用途 |
| --- | --- | ---: | --- |
| `displayLarge` | 57/64 | 400 | 极少使用的品牌级展示 |
| `displayMedium` | 45/52 | 400 | 大型展示 |
| `displaySmall` | 36/44 | 400 | 登录或关键空状态标题 |
| `headlineLarge` | 32/40 | 400 | 大页面标题 |
| `headlineMedium` | 28/36 | 400 | 页面标题 |
| `headlineSmall` | 24/32 | 400 | 工作区主标题 |
| `titleLarge` | 22/28 | 400 | 区域标题 |
| `titleMedium` | 16/24 | 500 | 列表项和组件标题 |
| `titleSmall` | 14/20 | 500 | 紧凑标题 |
| `bodyLarge` | 16/24 | 400 | 主要正文 |
| `bodyMedium` | 14/20 | 400 | 默认正文 |
| `bodySmall` | 12/16 | 400 | 次要说明 |
| `labelLarge` | 14/20 | 500 | 按钮和重要标签 |
| `labelMedium` | 12/16 | 500 | 紧凑控件标签 |
| `labelSmall` | 11/16 | 500 | 状态与辅助标签 |

紧凑面板、侧栏和表格必须使用对应的 Title/Body/Label，不得把 Hero 级字体缩放后塞入组件。禁止使用视口宽度直接缩放字号。

## 11. 间距、尺寸与布局

### 11.1 间距基线

采用 4dp 基线：

```text
4, 8, 12, 16, 20, 24, 32, 40, 48, 64
```

页面布局应优先使用 16、24、32；组件内部优先使用 8、12、16。禁止为了视觉微调随意新增 13px、19px 等一次性间距。

### 11.2 触控与稳定尺寸

- 所有可点击目标最小为 48x48dp；视觉容器可以是 40dp，但命中区域必须达到 48dp。
- 工具栏、导航、棋盘式比较区域、图标按钮和进度条必须定义稳定尺寸，内容变化不得造成布局跳动。
- 按钮文字不得被截断；空间不足时应换行、缩短文案或切换响应式布局。
- 表单控件必须有持久标签，不能只依赖 placeholder。

### 11.3 内容宽度

- 阅读型正文建议最大宽度 720px。
- 表单主体建议最大宽度 840px。
- 决策比较和行动工作区可扩展到 1200-1440px，但必须保留页面边距。
- 宽屏不得无限拉长正文或表单字段。
- 复杂比较表在 Compact 下必须切换为逐候选比较、分段视图或受控横向滚动，不得压缩到不可读。

## 12. Shape 与 Elevation

### 12.1 M3 Shape Scale

| Token | 半径 | 默认用途 |
| --- | ---: | --- |
| `none` | 0 | 表格边界、分隔结构 |
| `extraSmall` | 4 | 小标签、菜单项内部 |
| `small` | 8 | 紧凑 Surface、输入控件 |
| `medium` | 12 | 普通卡片和面板 |
| `large` | 16 | 大型容器和 Bottom Sheet |
| `extraLarge` | 28 | Dialog、大型 Sheet |
| `full` | 9999 | Chips、FAB、圆形按钮 |

同类组件必须使用同一 Shape Token。禁止页面自行创造圆角。密集运营界面优先使用 `small` 或 `medium`，不得把所有区块做成大圆角漂浮卡片。

### 12.2 Elevation

| Level | 用途 |
| --- | --- |
| 0 | 页面和静态 Surface |
| 1 | 可交互卡片、Navigation Rail |
| 2 | 浮动工具栏、搜索展开状态 |
| 3 | 菜单、Tooltip、Snackbar |
| 4 | Dialog 或拖拽中的组件 |
| 5 | 极少使用的最高临时层 |

M3 优先使用 Tonal Elevation 和 Surface Container 区分层级。阴影必须来自 Elevation Token，禁止在页面 CSS 中随意声明 box-shadow。

## 13. Motion 与状态层

### 13.1 Motion

- 小型状态变化使用 100-200ms Standard Motion。
- 页面内容器进入、展开和阶段切换使用 300-500ms Emphasized Motion。
- 禁止超过 700ms 的非必要业务动画。
- 禁止使用弹跳、漂浮、持续脉冲等与任务无关的动画。
- 必须支持 `prefers-reduced-motion`；Android 必须尊重系统动画缩放设置。
- 减少运动时保留状态反馈，但移除位移、缩放和复杂共享轴动画。

Android 交互运动矩阵固定为：

| 场景 | 过渡 | 时长 | 约束 |
| --- | --- | ---: | --- |
| 底部一级页面 | Fade Through | 100ms 退出、200ms 进入 | 不使用带层级或方向暗示的横向滑动 |
| 二级详情进入/返回 | Shared Axis X | 300ms | 返回方向必须与进入相反；减少运动时退化为淡入淡出 |
| 登录/注册差异字段 | Fade + 纵向展开/收起 | 200ms | 公共字段不得重建，不得清空输入、焦点或键盘状态 |
| Dialog | M3 默认淡入与轻微缩放 | 100-200ms | 不得加入弹跳或装饰性延迟 |

Compose 动画时长必须引用 `CareerMotionTokens`，不得在业务页面散落毫秒字面量。系统动画缩放为 0 时，过渡必须立即完成并保留最终状态反馈。

### 13.2 State Layer

交互状态遵循 M3 State Layer：

| 状态 | State Layer opacity |
| --- | ---: |
| Hover | 8% |
| Focus | 12% |
| Pressed | 12% |
| Dragged | 16% |

禁用内容默认 38% opacity，禁用容器默认 12% opacity。禁止只降低整个组件透明度导致边界、文字和背景一起失去层级。

### 13.3 异步反馈

- 触发保存、生成、删除等操作后必须立即显示可感知状态。
- 同一个提交按钮在请求期间必须防重复触发。
- 局部请求使用组件内 Progress Indicator 或 Skeleton，不得遮挡整个页面。
- 仅页面首次聚合加载可使用页面级加载状态。
- 超时必须提供重试，并保留表单草稿和稳定 `requestId`。

### 13.4 桌面导航吸附

导航吸附属于项目级品牌微交互扩展，不属于 MD3 标准行为，只允许在一级导航的桌面精细指针环境中使用：

- 导航项、图标、文字、链接命中区域、布局尺寸与焦点位置必须始终保持不变；吸附只能发生在独立的自定义光标视觉层。
- 自定义光标在桌面页面内以浅色实心圆无拖尾地跟随真实鼠标，并使用 `mix-blend-mode: difference` 反转其覆盖区域内的文字与图标。链接、按钮、标签页、菜单项和交互卡片可以参与磁吸；靠近目标时，圆形光标必须平滑变形成目标组件的完整尺寸和圆角。表单输入、滑块等需要精确指针定位的控件不得磁吸。光标层必须使用 `pointer-events: none`，并使用项目 Motion Token 完成吸附和回位。
- 只在 `(hover: hover) and (pointer: fine)` 且未开启减少动态效果时启用。
- 触摸、键盘导航和 `prefers-reduced-motion: reduce` 必须退回标准 MD3 State Layer。
- 吸附不能覆盖选中、悬停、焦点和禁用状态，也不能用于破坏性操作或密集表单控件。

禁止业务页面直接使用 `<md-*>`、Element Plus、浏览器原生弹窗或未经封装的 Headless Primitive。

### 14.3 Button

- Filled Button：页面唯一主要命令。
- Filled Tonal Button：重要但非主要命令。
- Outlined Button：次级命令。
- Text Button：低强调或 Dialog 辅助命令。
- Icon Button：编辑、删除、返回、排序等熟悉动作；必须提供 Tooltip 和无障碍名称。
- 禁止同一区域出现多个视觉权重相同的 Filled Button。
- 破坏性操作使用 Error 角色，并在不可逆时二次确认。

### 14.4 Text Field 与表单

- 长表单默认使用 Outlined Text Field；紧凑搜索可使用 Filled Text Field。
- 标签必须持久显示，placeholder 只提供示例。
- 错误必须同时显示错误文字和 Error 状态，不得只改变边框颜色。
- 必填标识必须在提交前可见。
- 校验应在字段离焦或提交后出现，禁止用户输入每个字符时反复弹出全局错误。
- 服务端冲突必须解释数据已在其他设备变化，并提供重新加载或合并路径。

### 14.5 Dialog、Snackbar 与 Tooltip

- Dialog 必须锁定焦点、支持 Escape、关闭后把焦点返回触发元素。
- 删除、批量调整和 AI 建议写入使用确认 Dialog。
- Android 恢复默认主题前必须说明会重置的外观偏好和本机背景，并明确账号与业务数据不受影响。
- Android 退出登录前必须确认；存在待同步操作时不得执行退出，应改为阻断说明，并在在线时提供“立即同步”。
- Snackbar 用于短暂操作反馈，同一时间只展示一个；重要错误不得只依赖自动消失的 Snackbar。
- Tooltip 用于图标按钮和不熟悉的图标，不用于承载关键业务说明。
- 禁止使用浏览器 `alert`、`confirm` 和 `prompt`。

### 14.6 Navigation

- 一级导航选中状态必须使用 M3 Active Indicator、图标和文字共同表达。
- 返回操作使用 Icon Button，不使用写着“返回”的大圆角按钮，除非它是空状态中的明确命令。
- Tabs 只切换同一页面内的同级视图，不用于跨业务模块导航。
- Breadcrumb 仅在三层以上桌面信息结构中使用，Compact 默认隐藏。

### 14.7 Data Table 与比较区域

- 表头、排序、选中、悬停、加载、空状态和分页必须使用统一 Token。
- 数值比较必须对齐单位和小数规则。
- 分数必须附带文字依据，不能把职业决策简化为颜色热力图。
- Compact 下不得保留最小宽度巨大的桌面表格并让整个页面横向滚动。
- 表格横向滚动时，页面导航和主要操作不得一起被滚出视口。

### 14.8 文件选择

- 文件选择必须使用系统 File Picker，不仿造文件系统。
- 上传前显示文件名、类型、大小和隐私提示。
- 进度、取消、失败重试和删除状态必须完整。
- 简历与背景图使用不同的 MIME、大小和隐私规则。

## 15. 业务页面模式

### 15.1 登录与引导

- 登录首屏直接提供登录或注册，不制作营销落地页。
- 自定义背景可用于登录 Page Canvas，但表单必须位于可读 Surface。
- 新用户引导按短步骤组织，显示进度、返回和保存草稿状态。
- 不要求用户首次进入就完成全部档案。

### 15.2 工作台

- 顶部只显示一个 Primary Action。
- 当前决策、今日行动和执行风险按扫描顺序排列。
- 没有数据时使用任务导向 Empty State，不展示功能说明清单。
- 不使用多个同权重卡片争夺注意力。

### 15.3 职业探索

- “职业方向”和“招聘岗位”使用 Tabs 或等价同级切换。
- 筛选在 Expanded 可常驻，在 Compact 使用 Modal Bottom Sheet 或 Drawer。
- 最多 3 个岗位的比较状态必须持续可见。
- 收藏、加入候选和加入岗位样本必须是不同语义动作，不得只靠图标颜色区分。

### 15.4 决策项目

- 五阶段使用局部 Step Navigation，不进入全局导航。
- 阶段推进条件在操作附近展示，不使用全局功能介绍文字。
- 证据必须显示来源、可信度和倾向。
- AI 输出固定呈现结论、依据、不确定性和下一步。
- AI 候选和修改建议必须通过明确确认操作写入。
- 对比结果必须同时展示分数、文字依据和信息缺口。

### 15.5 行动计划与复盘

- 本周、全局和成果使用同级 Tabs。
- 任务组件必须稳定展示类型、状态、耗时、截止时间和验收标准。
- 完成、延期、跳过和恢复必须有明确反馈。
- 完成任务后可立即填写成果，但允许稍后补充。
- 批量调整计划必须展示影响数量并二次确认。

### 15.6 历史记录

- 决策快照、旧报告、简历分析和旧路径按类型筛选。
- 旧数据必须明确标记为旧版，不得伪装成新决策项目。
- 删除历史记录前必须说明是否影响当前项目和行动计划。

### 15.7 AI 导师

- AI 助手是页面上下文导师，不是悬浮装饰。
- 必须展示 `generationMode`，但使用用户可理解的“模型生成/规则建议”等文字。
- 低置信度和 fallback 不得使用成功语气伪装成确定结论。
- 敏感档案发送外部模型前必须有有效授权。

## 16. 无障碍与本地化

### 16.1 对比度

- 正常正文至少满足 WCAG 2.2 AA `4.5:1`。
- 大号文字至少 `3:1`。
- 关键图标、焦点边界和控件边界至少 `3:1`。
- 自定义背景启用后必须重新执行对比度计算。
- 禁止用纯透明 Surface 假设任意背景都可读。

### 16.2 键盘与焦点

- 所有 Web 功能必须可用键盘完成。
- 焦点顺序必须与视觉和阅读顺序一致。
- 必须使用可见 Focus Ring，禁止无替代地移除 outline。
- Dialog、Menu、Tabs、Select、Date Picker 必须符合对应 ARIA Pattern。
- 拖拽排序必须提供键盘或按钮替代操作。

### 16.3 语义与屏幕阅读器

- 优先使用原生语义元素。
- Icon Button 必须有可访问名称。
- 装饰图标必须从辅助技术中隐藏。
- 状态更新使用适当的 Live Region，但不得重复朗读。
- 图表必须提供文字摘要或数据表替代。

### 16.4 中文与长文本

- 中文界面默认使用简体中文和中文标点。
- 不允许中英文无意义混排；必要技术术语首次出现时给出中文名称。
- 用户输入、职业名称和 AI 长文本必须支持换行。
- 任何文字不得溢出按钮、卡片、表头、Chip 或导航项。
- 日期、时区、金额和分钟数必须使用统一格式化工具。

## 17. Web 工程实现规范

### 17.1 组件封装

推荐目录边界：

```text
web/src/design-system/
  tokens/
  theme/
  components/
  services/
  adapters/
```

- `adapters` 封装 Material Web 或无样式交互基础。
- `components` 暴露项目统一的 Vue API。
- `services` 提供 Snackbar、Confirm、Theme 等全局能力。
- `tokens` 不得依赖业务模块。
- 业务页面禁止从 `@material/web` 直接导入。

### 17.2 Element Plus 迁移规则

- 新功能禁止新增 Element Plus 使用。
- 迁移后的文件禁止残留 `<el-*>`、`ElMessage`、`ElMessageBox` 和 `v-loading`。
- 迁移按实际路由进行，旧孤立页面不因样式迁移重新成为产品入口。
- 所有活动路由迁移完成并通过门禁后，必须删除 Element Plus 依赖、自动导入配置和样式覆盖。
- 禁止同时长期维护 Element Plus 主题和 M3 Token 两套系统。

### 17.3 CSS

- 业务 CSS 只能使用 Token，不得硬编码颜色、阴影、圆角和运动曲线。
- 允许使用布局尺寸和与业务数据相关的 CSS 自定义属性。
- 不使用 `!important` 覆盖组件视觉状态；确需使用必须登记例外。
- Portal、Dialog、Snackbar 和 Tooltip 必须继承当前主题作用域。
- Light、Dark 和高对比度不得复制三份页面 CSS。

### 17.4 图表

- ECharts 可以保留，但必须通过主题适配器读取当前 Token。
- 主题切换后图表必须实时更新。
- Tooltip、坐标、图例和数据标签必须满足对比度。
- 禁止在图表配置中散落固定十六进制颜色。

## 18. Android 工程实现规范

- App 根节点必须由统一 `CareerTheme` 提供 `MaterialTheme`。
- 所有界面颜色使用 `MaterialTheme.colorScheme` 或项目扩展颜色。
- 所有字体使用 `MaterialTheme.typography`。
- 所有形状使用 `MaterialTheme.shapes` 或映射后的 Shape Token。
- Android 12+ 的 `system` 来源使用 `dynamicLightColorScheme` / `dynamicDarkColorScheme`。
- Android 11 及以下必须使用品牌或账户种子色生成方案。
- 自定义背景按 Android 平台偏好保存，不覆盖 Web 背景。
- Room 可缓存最近主题和背景元数据；图片缓存必须可清理，不得进入业务数据库实体。
- WorkManager 同步主题时必须遵守平台 scope 和版本冲突规则。
- 系统栏、Navigation Bar 和启动画面必须与当前 M3 主题一致。

## 19. 设计与工程验收门禁

### 19.1 静态门禁

目标态必须满足：

- `element-plus` 和 `@element-plus/icons-vue` 不在生产依赖中。
- 活动页面不存在 `<el-*>`、`ElMessage`、`ElMessageBox` 和 `v-loading`。
- 业务文件不存在未经允许的颜色字面量。
- 业务文件不存在未经允许的 box-shadow、圆角和 easing 字面量。
- 所有 Icon Button 有 Tooltip 和 accessible name。
- 所有图片有正确的替代文本或明确标记为装饰。

### 19.2 主题矩阵

每个核心流程必须验证：

```text
Custom Seed Dark
Custom Image Light
Custom Image Dark
High Contrast
Background disabled
Background loading failed
```

### 19.3 视口矩阵

至少覆盖：

```text

600x960
840x1080
1440x900
```

不得出现非预期水平溢出、文字遮挡、按钮尺寸跳动、Dialog 超出视口或背景导致不可读。

### 19.5 Android 验收

- Debug/Release 构建和 Lint 零失败。
- 系统动态颜色、品牌色和自选种子色均可启动。
- Android 12+ 真机验证系统 Monet。
- Android 旧版本验证回退主题。
- 背景不同步时 Web 与 Android 互不覆盖。
- 同步配色时两端语义颜色一致。

## 20. 迁移策略

Web 的阶段 0 至阶段 5 已完成；本节继续作为 Android 和跨端同步实施顺序，以及未来重构时的回归依据。

### 20.1 阶段 0：规范与原型

- 锁定 M3、Material Web、Material Color Utilities 和 Compose 版本。
- 建立 Design Token 和主题生成器。
- 完成基础组件目录及组件展示页。
- 使用登录、工作台和决策项目各一个区域验证视觉密度。

### 20.2 阶段 1：应用框架

- 重构 Theme Provider、Top App Bar、Navigation Bar/Rail/Drawer。
- 替换 Snackbar、Confirm、Dialog、Loading 等全局服务。
- 建立 Light、Dark、高对比度与减少运动支持。

### 20.3 阶段 2：核心页面

按顺序迁移：

```text
登录与引导
-> 工作台
-> 职业探索
-> 决策项目
-> 行动计划与复盘
-> 个人档案
-> 历史记录与设置
```

每迁移一个页面必须同时更新单测、E2E 和视觉截图，不允许最后集中补测试。

### 20.4 阶段 3：个性化

- 加入品牌、自选颜色和图片取色。
- 加入 Web 本地背景和隐私处理。
- 加入主题预览、恢复默认和失败回退。

### 20.5 阶段 4：跨端同步

- 新增共享、Web、Android 三层账户偏好。
- 背景资源接入对象存储。
- Android 接入系统动态颜色和平台独立背景。
- 验证离线、并发更新和资源删除。

### 20.6 阶段 5：移除旧体系

- 删除 Element Plus 依赖和配置。
- 删除旧 Clay/Element 主题变量及无引用样式。
- 删除不再需要的旧 UI 组件；旧数据读取能力继续保留。
- 全量执行质量门禁和真机验收。

## 21. 规范治理

- 规范使用语义化版本：重大视觉或 Token 破坏性变化升级主版本。
- 新组件必须先定义 Token、状态、无障碍和响应式行为，再进入业务页面。
- 偏离本规范必须记录：原因、影响范围、负责人、到期时间和清理编号。
- 临时例外不得成为复制模板。
- 每次发布前由设计和工程共同检查核心主题矩阵。
- Figma Variables、代码 Token 和本文档版本必须一致。
- 本规范未覆盖的情况优先参考官方 M3，不得直接复制其他产品的视觉实现。

## 22. 完成定义

只有同时满足以下条件，才能宣布 MD3 重构完成：

Web 与 Android 的活动界面代码迁移已经完成，以下跨端完成定义仍未全部满足。

1. 所有活动 Web 路由已使用项目 M3 组件和 Token。
2. Element Plus 已从生产依赖移除。
3. Web 与 Android 使用同一语义颜色契约。
4. 品牌、自选颜色、图片取色、Light、Dark 和高对比度通过验收。
5. Web 与 Android 可使用不同背景且不会互相覆盖。
6. 动态背景不破坏对比度、性能和隐私。
7. 360px、600px、840px、1440px 布局通过视觉回归。
8. 键盘、焦点、屏幕阅读器和减少运动通过检查。
9. 完整职业决策与行动闭环 E2E 零失败。
10. Android 真机完成系统 Monet 和账户主题验收。
11. 设计 Token、组件目录、设计工具和本文档保持同一版本。
